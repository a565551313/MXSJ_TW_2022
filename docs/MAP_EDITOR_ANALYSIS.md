## 一、项目整体架构与子系统全景分析

`MXSJ_TW_2022` 是一个围绕《夢想世界》TW `v2.27.2` 客户端建立的**逆向研究、资源编解码、可视化编辑工具链与服务端复刻工程仓库**。全仓严格遵循“**原包只读、工具与数据分层、核心逻辑零 GUI 耦合、Windows 玩家开箱即用**”四条核心工程准则。

### 1.1 五大核心子系统职责与边界

1. **原始客户端运行时与加密归档层（只读基线）**
   - `mx.exe`（`6,569,984 B`）与 `mxmain.dll` / `render.dll`：负责 `0.1M` 地图加载（`CMap` 类簇 `0x004b8800..0x004b9c00`）、`GEPJ` 分片 JPEG 解码（`0x00637420`）、`LZO1X-1` 快速解压（`0x0060ea90`）、8 方向 `CAStar` 寻路（`0x004bac30`）、`0SLF`/`FLS` 包虚拟文件系统、精灵渲染与原生 TCP 协议加解密。
   - `data/script.fls`（`5,002` 条 XOR 加密并混淆 opcode 的 Python 2.5 marshal 字节码条目）：承载全部客户端业务逻辑、UI 控制器、场景热替换映射表（`NEW_RPL_MAP`、`RPL_MAP_BLK`）、小地图与传送点定义。
   - `data/*.fls`（`interface.fls`、`icon.fls`、`stand.fls`、`walk.fls`、`effect.fls` 等）：客户端 UI 布局、贴图、角色与特效精灵资源包。

2. **逆向解析与资产提取工具链（`tools/`）**
   - `tools/fls_batch_decoder.py` & `tools/data-parser/`：解析 `0SLF`/`FLS\0` 归档目录（`mx_path_hash` 路径哈希）、`i0_sprite` 精灵帧图像与 `.dlg` 界面布局。
   - `tools/decompiler/`（`batch_decompile.py`、`recover_entries.py`、`pack_and_encrypt.py`）：配合 `script_fls_keys.json` 解密并反编译定制 Python 2.5 字节码，支持安全重打包生成派生 `.fls`。
   - `tools/native_channel/`（`0.1.0`）：离线复现并对照验证原生 TCP 握手密钥派生、流密码器与 LZW 数据帧编解码。
   - `tools/devkit/check_windows_compat.py`：全仓统一的 Windows 文件名保留字、大小写冲突、`encoding="utf-8"`、硬编码 POSIX 路径与跨平台兼容性静态检查器。

3. **服务端复刻与协议网关体系（`server/` + `gateway_py25/`）**
   - `server/mock_server/`：Python 实现的协议级 Mock 网关与世界服，配合 `server/docs/csv_checks/staging/` 下从脚本静态提取的场景表（`sceneid2name_id2name.csv`）、NPC 坐标表（`npcposdata_records.csv`、`minimapnpcpos_pos_records.csv`）与对白/商店数据闭环验证进图与交互。
   - `server/cpp_skeleton/`：C++ 网关/登录服/世界服分层骨架实现。

4. **客户端 UI 布局可视化编辑器（`ui_editor/`，`v0.16.0`）**
   - 成熟的 `PySide6` 桌面编辑器标杆：支持 `interface.fls` 浏览、可视化拖拽、精灵族预览导出、批量导入 `.dlg`、严格只读模式 vs 二次确认宽松写回原包模式，以及写前检查 + 原子替换 + 写后逐条重读校验（782 项单测）。

5. **客户端地图编辑器与编译套件（`map_editor/`，本轮升级至 `v1.0.0`）**
   - 本次工作的核心对象：此前停留在第一期只读原型（`v0.1.0`），存在 `GIRB` 解压失败、部分真实地图解析报错、区块语义误判、无任何编辑/保存能力、56% 地图无名称等瓶颈；本轮已完成从底层二进制逆向到 Studio 图形工作台的全量重构与闭环验收。

## 二、原版地图编辑器（`v0.1.0`）深度诊断与四大核心缺陷根因

在拉取 Google Drive `MAP` 目录下的完整客户端地图分卷（`map.z01` `94,371,840 B` + `map.z02` `94,371,840 B` + `map.zip` `79,056,090 B`，共 **101 张 `.map` 地图，`11,763` 个扇区，`20,036` 个前缀遮罩**）进行全量扫描并反汇编 `mx.exe` 后，精准定位了 `v0.1.0` 的全部问题根因：

### 2.1 根因一：3 张现行主力地图直接报 `MapFormatError` 无法打开
- **现象**：`test_new2_1054.map`（现行主城**明月城**，`7300×5020`，尾部多 `541 B`）、`test_1005.map`（现行**天水平原**，尾部多 `9,889 B`）、`test_2302.map`（现行**南遙戰士師道殿**，尾部多 `18,951 B`）在旧版解析器中因断言 `cursor == file_length` 直接抛出损坏错误。
- **真相**：多益内部编辑器在原位修改单个扇区时以 `"rb+"` 模式将变大的新扇区追加到文件末尾并更新 `sector_offsets[i]`，旧扇区字节成为未被任何偏移引用的尾部死空间；`mx.exe` 只按偏移表寻址从不检查 `EOF`。
- **修复**：`MapDocument` 精确记录 `trailing_bytes = file_len - max_active_end`，正常打开全部 101 张地图，并在“另存为”时自动紧凑重排消除历史死字节。

### 2.2 根因二：`GIRB` 解压在 **60 / 101 张地图（59.4%）** 上崩溃失败
- **现象**：旧版 `girb.py` 猜测 `GIRB` 使用某种未知变种 RLE/LZ 算法，并在第 315 行将匹配指令后的 `trail = t & 3` 强行置为 `0`，导致全量 **101 张地图中有 60 张（共 2,670 个扇区）解压失败**（包括仓库自带样本 `1034.map`、`1035.map`）。
- **真相**：反汇编 `mx.exe` `0x0060ea90` 并在 Unicorn x86 模拟器中对 **1,360 组实机载荷**逐字节执行对拍证实：`0x0060ea90` 是**100% 标准 32 位 `LZO1X-1` 解压函数**！匹配结束后 `t & 3`（1~3 字节）表示紧随其后的尾随字面量并直接跳转 `match_next` 状态。修复后 **11,763 / 11,763（100.000%）个 `GIRB` 块与 20,036 / 20,036（100.000%）个 `PrefixRecord` 遮罩块全部零误差解出**。

### 2.3 根因三：`LLEC`、`GIRB` 与 `PrefixRecord` 物理语义倒置
通过对 `mx.exe` `0x00487700..0x004bc100` 与 `script.fls` 中 22 个地图相关脚本的交叉反编译，彻底厘清了三类数据块的真实引擎语义：
1. **`LLEC`（反向四字符码即 `"CELL"`，固定 `192 B = 16×12` 字节，`20×20 px`/格）—— 真正的通行与阴影网格**：
   - 全量 `2,256,779` 个有效格 **100.000%** 取值落在 `{0, 1, 2, 3}`：
     - `0`（`64.39%`）：普通可行走平地；
     - `1`（`30.89%`）：不可行走阻挡格；
     - `2`（`4.72%`）：屋檐/树荫可行走格（角色走入时半透明着色，但**可行走**）；
     - `3`（`0.004%`）：阴影阻挡格（不可行走）。
   - `CAStar`（`0x004bac30`）精确判定：`cell & 1 == 0` 可通行（代价 `0x7575`），`cell & 1 == 1` 阻挡（`0xFFFF`）。
2. **`GIRB`（反向四字符码即 `"BRIG"` = Brightness，解压固定 `2,400 B`）—— `80×60`（`4×4 px`）角色/地表动态光照亮度图**：
   - `mx.exe` `0x004b9220` 读取 `row * 40 + (lx >> 1)`，低 4 位对应偶数列 `2k`、高 4 位对应奇数列 `2k+1`。
   - 中性值为 `8`（双采样字节 `0x88`，即 `8 / 8 = 1.0×` 原色亮度）；`< 8` 为洞穴/树影压暗，`> 8`（最高 `15`，`1.875×`）为灯笼/阳光高光增亮！
3. **`PrefixRecord`（`20 B` 头 `<iiIII` + `LZO1X-1` 载荷）—— 2-bit Alpha 前景遮挡蒙版**：
   - 解压大小恒等于 `((width + 3) // 4) * height` 字节，每字节按 LSB-first 存放 4 个水平像素的 2-bit Alpha（`0, 85, 170, 255`）。
   - 每个扇区头部的 `record_refs` 严格等价于 `Win32 ::IntersectRect(&rcSector, &rcMask)`，其中 `rcSector = {ox, oy, ox + 319, oy + 239}`，`rcMask = {rx, ry, rx + rw, ry + rh}` —— 在全部 **11,763 个扇区上达成 11,763 / 11,763（0 偏差）数学恒等**！

### 2.4 根因四：`NEW_RPL_MAP` 热替换与变体命名导致 57 张地图丢失场景名/NPC
- 客户端 `script/mxgame/map/map.py` 定义了 `NEW_RPL_MAP`（例如 `1054 -> 'test_new2_1054'`、`1001 -> 'new2_1001'`、`1025 -> 'test_new2_1025'`、`1005 -> 'test_1005'`、`2302 -> 'test_2302'`）。旧版 `SceneTable` 只支持纯四位数字键，导致全部现行主城地图均无法匹配名称、传送点与 NPC。
- 重构 `tools/build_scene_table.py` 与 `client/scene_table.py` 后，**101 / 101（100.0%）** 地图文件全部准确解析场景名称、现行/历史版本标签、283 个传送阵与 1,293 个 NPC 刷新点。

## 三、`map_editor` v1.0.0 完整功能实现清单

1. **二进制无损读写与编译引擎（`core/`）**
   - `lzo1x.py`：100% 兼容 `mx.exe` `0x0060ea90` 的 `inflate_lzo1x` / `deflate_lzo1x` 编解码器（统一色块 2,400B 输出与官方编译器完全一致的 22 字节黄金码流）。
   - `gepj.py`：支持 `GEPJ` 解码、重编码、任意大图自动切片编译（含边缘像素钳位消除 4:2:0 振铃伪影）及 `GIRB` 动态光照合成渲染。
   - `girb.py`：4×4px 4-bit 亮度网格读写、圆形光斑画笔、扇区重置与 RGB 光照调制。
   - `mask.py`：2-bit Alpha 前景遮罩编解码、RGBA 实景镂空提取、PNG 导入生成新遮罩及 `IntersectRect` 扇区索引自动重建。
   - `blk.py`：`.blk` 读写、`LLEC` 双向同步及 `ServerPos ↔ ClientPos` 精确双向坐标变换。
   - `pathfinding.py`：8 方向 `CAStar` 寻路器与全图可行走连通域/孤岛统计器。
   - `mapfile.py`：完整的 `MapDocument` 编辑模型、画笔/矩形/直线/油漆桶工具、无损 `to_bytes()` 序列化及临时文件原子落盘 + 写后重解析自检（`save(..., verify=True)`）。

2. **零 Qt 状态机、100 步撤销重做与严苛/宽松保护（`ui/viewmodel.py`）**
   - 所有画笔、矩形、直线、油漆桶、光照涂抹、遮罩增删移、底图替换、`.blk` 导入均封装为可逆 `UndoCommand`（最多 100 步 `Ctrl+Z` / `Ctrl+Y`）。
   - 默认启用**严苛保护模式**（拒绝覆盖任何已扫描客户端源地图或当前打开源地图）；支持显式切换**宽松模式**并在 GUI 弹出二次确认后写回。

3. **Studio 图形工作台（`ui/widgets.py`）与全功能 CLI（`cli.py`）**
   - 三栏专业深色工作台：左侧实时搜索筛选地图浏览器（含现行主城高亮）+ 中央多图层交互画布（`1..8` 八大工具模式、实时 HUD 状态条、可点击跳转全彩鹰眼小地图）+ 右侧四标签检视面板（图层与画笔 / 前景遮罩镂空预览 / NPC 与传送点双击定位及一键寻路 / 底图 `.blk` 同步与健康度审计）。
   - 自动加载客户端内置字库（`Fonts/FZLanTingYuan-DB-GBK.ttf`、`simhei.ttf`），确保简繁中文在 Windows 与 Linux 下均清晰锐利无乱码。
