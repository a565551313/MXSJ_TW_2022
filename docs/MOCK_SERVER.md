## 现有能力

Mock 使用 socket 和每连接线程，提供报文构造、会话分派和 JSON 账号／角色存储。
覆盖选区、登录、创建／选择角色、属性初始化、进图、部分 NPC 对话与传送、移动、聊天、心跳、时间／日历同步及系统设置快速重登。
这只是相应模拟链路，不代表完整世界、碰撞、战斗、账号安全或并发持久化。

## 默认启动的副作用

先在完整备份的测试副本审查 `main()`、`ensure_client_ready()` 和补丁函数；不要直接在原始仓库运行无参数服务。

- 默认监听 `0.0.0.0:3134`，不是仅回环地址。
- 默认调用客户端准备流程，可备份并修改 `data/script.fls` 的相关内容。
- 准备流程还会写 `nocheck` 开发模式配置。
- `--no-patch` 仅控制 FLS 补丁分支，**不等于启动完全只读**。
- `--patch-client` 是显式客户端修改操作；`--restore-client` 依赖实际备份，不是通用撤销工具。
- 默认账号／角色 JSON 为客户端根目录下 `mock_accounts.json`；`--root` 自动发现不能代替人工确认目标。

若以后需要与真实客户端联调，应明确授权、隔离网络、显式指定测试副本与数据库路径，并用假账号。不要将开发模式、端口暴露或真实凭据带入生产。

## 已确认的非生产行为

| 代码位置（函数／类） | 当前行为与风险 |
|---|---|
| `AccountStore.get_or_create_account` | 已有账号不比较传入密码摘要即返回角色，不是认证实现 |
| `ClientSession._on_quicklogin` | 读取请求 key 后按角色 ID 查找，未验证该 key 的授权；固定开发 key 不是真实票据 |
| `AccountStore._save` | 直接写 JSON，异常仅告警；没有原子文件发布或数据库事务保证 |
| `AccountStore._load` | 加载失败后初始化新存储，可能掩盖损坏并改写原文件 |
| 会话处理与共享存储 | 部分调用直接修改状态／保存，不能从局部 lock 推导全局并发一致性 |
| `main` | 每连接线程及开发默认配置，不具备完整正式连接资源治理 |

这些行为适用于受控模拟，不能作为正式服务端的安全默认值。
后续建议将客户端准备与服务启动分开，并抽取经独立核验的帧／报文样例，而不是整体复制 Mock 业务逻辑。

## 如何理解回环测试

```bash
# 从仓库根执行；先阅读下述临时文件副作用
python3 mock_server.py --self-test
```

当前 `main()` 在客户端准备／正式监听之前进入自测分支。自测建立临时回环 socket，验证多个阶段；不启动 Windows 客户端，也不运行恢复的游戏脚本。
但它不是完全无副作用：使用固定 `/tmp/test_mock_accounts.json` 与 `/tmp/test_mock_nocheck`，开始时可能删除同名旧文件，结束时清理。运行前确认这些路径无其他工作数据；此实现也不能冒充 Windows 跨平台测试入口。

通过只证明该测试驱动与实现满足当前断言，不证明原生客户端、所有报文或业务安全。当前结果与执行轮次见 STATUS，不沿用日志中的“100%”作为全项目验收结论。

## 协议文档冲突的处理

历史研究记录曾按对应链路写 `0xFF` 后续读 2 字节；当前 Mock 的 `MAX_LEN_BYTES = 3`，自测按 `SetMaxLenBytes(3)` 构造长帧。
**不能把两者写成无版本范围的统一结论**。本轮不修改协议或重新裁定所有链路；后续变更必须绑定客户端构建、连接阶段、原始字段证据与独立测试，不能只改注释或测试期望值。
