# 恢复稿字节字面量可读化：取样与判定规则（2026-10-27）

本文件记录 `script_editor` 0.6.0.dev11 的取样结果，用于核对"读法"是否可信。
**这些文本只用于说明显示效果，不参与编译、不写回源码、不进入任何包。**

## 1. 为什么不能直接替换

恢复稿里的 `'\\xa5u\\xaf\\xe0...'` 是 Python 2 的 `str` 常量，值是**台服 MBCS 字节**
（反编译器把每个字节按 latin-1 印成一个码位，所以 0xA5 才显示成 `\xa5`）。
客户端在脚本里比较的是**这些原始字节**；把字面量改写成 `'只能使用...'`，
源文件（UTF-8）重编出的 `str` 就变成了 UTF-8 字节，行为随之改变。
所以编辑器只提供**显示层**：悬停提示与只读对照报告，两者都不会写回任何文件。

（台服文案优先 cp950），由使用者判断，而不是替人拍板。

## 3. 给出读法的条件（缺一不可）

1. 整个字面量能还原成**一条字节流**（Python 2 `str` 语义：`\xa5u` 里的 `u` 是字节 `0x75`，
   与前后 `\xNN` 同属一条流；按"只抓 `\xNN` 段"解码会错位——早期实现就把 `只能` 拆成
   `只` + 乱码，已改掉）；
2. 该编码**严格解码**成功；
3. 重新编码得到的字节与原文**逐字节相同**；
4. 解码结果至少含一个非 ASCII 字符（纯 ASCII 转义如 `'\x41\x42'` 不声称"可解码"）。

不满足就**不说**：`\n` / `\\` / `\u4e2d` / 八进制转义、`r'...'` 原始字符串、
已含原生非 ASCII 的字面量、单独一个 `\xNN`（截断的双字节对）都不给读法。

## 4. 界面入口

- **悬停**：鼠标停在这类字面量上显示读法，首行固定写"只读预览 · 源码字节未改"；
  可读的字节串在编辑器里带**点线下划线**（只是样式）。
- **编码 → 字节字面量 → 可读对照（只读）**：整个文件逐处列出"行号 / 原文 / 各读法"，
  可复制；对话框只读，没有保存或替换入口，正文也不含任何语句（因此它不是"改写后的源码"）。
- 反向操作仍然照旧：选中真实文案 → 「编码 → 选中文案 → Big5 字节…」生成字节字面量。
