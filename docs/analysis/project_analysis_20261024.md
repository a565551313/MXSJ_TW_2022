## 1. 项目定位

围绕《夢想世界》台服客户端 **v2.27.2**（多益网络）的四条主线：

| 主线 | 现状（STATUS §2，2026-10-23） |
|---|---|
| 客户端逆向研究 | 双 VM 字节码反编译、0SLF 路径哈希、`.dlg` 布局解码、原生 TCP 信道专项（`tools/native_channel` 0.1.0） |
| 工具链 / 编辑器 | 资源编辑器 0.4.3、UI 编辑器 0.16.0、地图编辑器 v1.0.0、脚本编辑器 0.6.0.dev9 |
| Python 服务端重建 | `local_server` SQLite 账号/会话/角色元数据（68/68）；正式服其余为契约设计 |
| 静态数据复核 | Catalog → FastAPI → React 只读复核链（Catalog 34、API 27、Web 112 通过） |

项目自我定位诚实且贯穿全部文档：**"能展示 ≠ 能运行，能运行 ≠ 正确，测试通过 ≠ 原生验收完成"**。这是本项目最值得保留的纪律。

## 4. 突出优势

1. **文档与证据纪律是核心竞争力。** AGENTS.md（规则）/ STATUS.md（状态）/ ROADMAP.md（路线）/ evidence JSON（绑定基线的检查记录）/ archive（历史快照）五层分离，每轮结论可追溯到具体分支、提交、SHA 和测试计数；对"未验"事项全程显式声明，没有笼统的"全部可用"。
2. **编辑器三件套达到生产级工程质量。** 全部实现原子发布、源包/别名保护、写后逐条校验、失败回滚；UI 编辑器针对 AI 审查逐条复核（只修属实项）；地图编辑器刚完成 101/101 全量语料往返验证。
3. **工程门禁成体系。** ruff + `check_windows_compat.py` + `bootstrap.py --check-only` 三件套在各组件例行执行，且结果如实报告（含跳过与基线失败）。
4. **锁定输入完整性机制。** `data/script.fls` 与 `script_fls_keys.json` 的 SHA-256 在 AGENTS.md 中固化，每轮开工核对——这在多人/多 Agent 协作的逆向项目里是关键防呆。

## 5. 问题与风险（按影响排序）

### P0 — 仓库体积与许可

- 586.7 MB 受控文件 + 371 MB `.git`，其中约 400 MB 是客户端二进制、CEF 运行时（根目录与 `exe/` 各一份）、OGG、商业字体。[STATUS_HISTORY §3.4](../archive/STATUS_HISTORY.md#s3-3-4) 已记录用户决定暂不动，但这是长期克隆/备份成本的主要来源。
- 根目录无 LICENSE，客户端材料再分发权利未确认；恢复引擎另有许可要求。

### P0 — Windows 原生验收全线缺口

- 所有"通过"均来自 **Linux 沙箱 offscreen**（PySide6 + 系统库桩）或回环 HTTP 测试；三个编辑器的 EXE 在 Linux 因缺 `libpython3.11.so` 从未产出，Windows 实机冒烟（ROADMAP 阶段 B）从未执行。
- 后果：工具链的真实交付形态（双击 bat → EXE → 真机加载编辑后资源）目前**无任何已验证路径**。

### P1 — 文档一致性漂移

- `README.md` §2"当前能力与完成度"表明显落后于 STATUS：UI 编辑器写 0.8.4（STATUS 已 0.16.0）、地图编辑器写"GIRB 300/429 扇区仍解不出"（STATUS 10-23 已 11,763/11,763 全解）。README 自称"2026-10-18 核对"，但两周内 STATUS 已推进多轮，两文件间无同步机制。
- `docs/STATUS.md` 单文件 **0.5 MB**，历史轮次按时间倒序无限堆积（§3 已到 3.10+），新成员检索成本高；ROADMAP 停留在 2026-10-18。
- 存在 `mock_server (1).py` 这类带空格括号的可疑文件名（疑似误提交副本），建议核实后清理。

### P1 — 脚本编辑器环境债务

- 4 失败 + 2 错误源于缺 `xdis` 与 Qt 运行库，与 master 基线相同——即"已知红但未修"。GUI 新用例在本机不可执行，恢复引擎的可信度无法通过 GUI 路径增量验证。

### P2 — 服务端与原生协议瓶颈

- 原生 TCP 加密（`C_net`/SetSeed 信道）仍未攻克，正式服仅 SQLite 账号/会话/角色元数据，无可进图服务；`mock_server_v2` 全链路只有用户 2026-10-21 的口述记录，**我方未复现**（无抓包/日志），STATUS 已如实标注。
- 伤害公式研究（2026-10-22 归档）：4791/2429 两条指令仍歧义，候选唯一性未定。

### P2 — 依赖与 CI

- 无 `.github/workflows`，CI 是 ROADMAP 阶段 A 的待办而非现实；`npm audit` 1 moderate / 2 critical（Vitest 开发依赖链，未处置）；Python 侧无统一锁定方案（各组件自带 requirements）。
- `tools/client_patches` ruff 328 条为最大单点技术债（v3.3 作废后待原生重做）。

## 6. 结论与建议

**总体判断**：这是一个文档纪律和工程质量显著高于平均水平的逆向研究 + 工具链项目，"诚实的状态管理"本身就是稀缺资产；短板集中在**交付形态未验证**（Windows/EXE/原生客户端）和**仓库治理**（体积、许可、CI、文档漂移）。

建议按优先级（均需用户授权，本文不构成自动开发授权）：

1. **仓库瘦身评估**（阶段 A 延伸）：确认本地备份后，将工具不依赖的客户端二进制（`music*/`、CEF、安装/更新器）移出 Git 跟踪，保留白名单（`mx.exe`/`mxmain.dll`/`exe/python27*.dll`/`data/*.fls`/`map/*.map`/`Fonts/`）；同步处理 LICENSE 与再分发边界。
2. **建立 CI**（ROADMAP 阶段 A 既定产物）：Linux 核心 + 前端检查 + wincompat/ruff 门禁，分开报告 GUI 与外部语料跳过。
3. **README ↔ STATUS 同步机制**：README §2 改为引用 STATUS 或加"核对日期 + 落后即红"的规则；STATUS.md 可拆分为"当前状态 + 历史档案"两个文件。
4. **Windows 真机冒烟计划**（阶段 B）：三个编辑器 bat/EXE + 编辑后资源回客户端加载，按 ROADMAP 的验收清单逐项回填。
5. **补齐环境债务**：script_editor 的 `xdis`/Qt 依赖修复或明确跳过原因；`npm audit` 逐项处置（禁止 `--force`）；Python 依赖锁定方案选型。
6. **清理疑似误提交文件**（`mock_server (1).py` 等）与 `tools/client_patches` 的 ruff 债务分期处理。
