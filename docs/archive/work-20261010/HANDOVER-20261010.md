### 3.1 加密算法破解 ✅（算法已还原；通信密钥未获得）

**算法**: 自定义 8 状态流密码（Stream Cipher）

```python
# 加密核心（伪代码；实际实现见 im_crypto.py 的 IMProtocolCrypto）
def encrypt(data, ctx):
    for i, byte in enumerate(data):
        state = ctx.state & 7
        xored = ctx.key[state] ^ byte
        index = (state << 8) | xored
        data[i] = ENC_SBOX[index]
        ctx.state = (ctx.state + 1) & 7
```

**密钥派生**: 链式 S 盒派生（8 个 KeySbox 表）

**协议帧格式**（推断，尚无真实报文验证）:
```
[加密( uint16_be(总长度,含长度字段本身2字节) + uint16_be(命令字) + payload )]
```

**关键文件**:

## 7. 重要发现和注意事项

### 7.1 映射表 v4.3 重大纠正（必读！）

任务 B 的 v4.3 纠正了之前 v4 的 **4 处误判**，基于 1000-20000x 证据:

| 编码字节 | 旧 v4（错误） | v4.3（正确） |
|---------|--------------|-------------|
| **0x98** | MAKE_FUNCTION | **STORE_NAME** |
| **0xE0** | BUILD_MAP | **IMPORT_NAME** |
| **0xFB** | STORE_NAME | **MAKE_FUNCTION** |
| **0x42** | POP_TOP | **BUILD_CLASS** |

> ⚠️ **警告**: 基于 v4 映射表的旧分析报告（`netserver_py_decompiled.md`、`任务A深入-表B破解报告.md`）需要用 v4.3 重新审视。如需重新解码，请使用 `mapping_table_v4.json`（v4.3 版本）。

### 7.2 多变体 S 盒（重大发现）

**同一个字节在不同 code object 中可以有不同的含义和尺寸！**

例如 `0x6C`:
- 在逻辑代码中 = `UNPACK_SEQUENCE`（3 字节）
- 在数据代码中 = `BINARY_?`（1 字节）

**影响**: 破解未知 opcode 时必须考虑多变体可能性，不能假设全局唯一映射。

**证据**: `mapping_table_v4.json` → `table_b` → `0x6C-dual`

### 7.3 跳转基址怪癖

| 指令 | 跳转基址 | 说明 |
|------|---------|------|
| `B7` / `E3` | `pos + arg` | 非标准（通常是 `pos+3+arg`） |
| `A2` | 绝对跳转 | 目标 = arg |
| `E5` / `AF` / `D3` | `pos + 3 + arg` | 标准相对跳转 |

### 7.4 编码规律

- **BINARY-1B 类**: `{05, 09, 15, 23, 3F}` — 1 字节参数的二进制运算
- **终止对**: `(05, 30)` 出现 11K 次
- **`(43, 5A) → STORE_ATTR`**: 343/343 次验证
- **0x71 = STORE_FAST**（3 字节指令，不是无参数）

### 7.5 协议相关

- **CJK 字符串为 Big5 编码**（不是 UTF-8/GBK）
- **商城协议用 `C2S`/`S2C` 前缀**（非 `C2GS`/`GS2C`）
- **命令字编号规律**: C→S 用 `0x00xx`，S→C 用 `0x10xx`，心跳用 `0x00FF`/`0x10FF`（规律为推断，数值未证实）
- **函数签名来自调试字符串**（`Name(p=%s,...)`），部分模块无调试串

### 7.6 地图相关

- **GEPJ 不是标准 JPEG**: 共享头 + 12 段独立扫描数据，需要重组
- **LLEC 网格**: 192 字节 = 16列×12行，值 mostly 0/1，边缘有 2/255
- **不要把网格图当成已证实的碰撞图** — 可行走语义未证实

### 7.7 分析边界
