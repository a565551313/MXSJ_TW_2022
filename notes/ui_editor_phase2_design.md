# MXSJ UI 编辑器二期设计（撤销/重做 + 像素级绘制）

> 2026-10-13 定稿。对象：`ui_editor/`（现行 0.3.3）。
> 一期（编解码、渲染、画布编辑、新建、保存 PNG）与二期 M1（回写
> `.fls`，0.2.x 已完成）不在本文范围。本文只设计二期剩余两块：
> **M2 撤销/重做**、**M3 像素级绘制**。施工顺序 M2 → M3。

## 0. 通则

- **安全语义不回退**：所有二期功能都只作用于内存中的文档；写回
  资源包仍走既有的复制+补丁+三道硬校验流程（0SLF 密钥沿用、
  条数/他条字节校验、回读逐字段一致才清 dirty）。
- **数据层零 Qt**：撤销历史、九宫格、对齐计算都放 `core/`，
  UI 层只接信号；沿用现有分层（`core` 不 import PySide6，精灵
  编码的 Pillow 依赖除外，该依赖已在 0.3.2 引入）。
- **每步可验收**：每个里程碑都有对应的自动测试（现行测试框架：
  `LD_LIBRARY_PATH=/tmp/qtstub QT_QPA_PLATFORM=offscreen python -m unittest`，
  无 pytest），且手工验收清单写入本文。

## 1. M2 撤销/重做（0.4.0）

### 1.1 问题

现在任何误操作（拖错位置、删错控件、改错属性）都没有后悔药，
只能不保存重开。画布编辑越往像素级走，误操作越多，撤销是前提。

### 1.2 方案：文档快照时间线（不做命令模式）

布局文件本身不大（一期语料单张 .dlg 普遍 KB 级），全量快照的
内存与速度都够用；且编辑入口分散（属性面板逐字段直改 props、
画布 itemChange 连续改几何、结构操作走 Document 方法），逐个
操作写命令对象成本高、易漏。快照法只认一个不变量：**任何已
提交的编辑结束时，文档处于一个可序列化状态**。

数据结构（`core/model.py` 的 `LayoutDocument` 内）：

```text
_history: list[list[dict]]   # to_dicts() 的时间线，[0] 为打开时
_h_index: int                # 当前状态在时间线中的位置
_last_merge_key              # 上一次 checkpoint 的合并键
```

接口：

- `reset_history()`：打开/新建文档后调用，时间线只含当前状态。
- `checkpoint(merge_key=None)`：编辑提交后调用。把当前状态写入
  时间线：若 `merge_key` 与上一次相同、且当前正位于时间线末端，
  则**替换**末端状态（合并连续同类编辑，见 1.3）；否则截断
  `_h_index` 之后的重做尾巴后追加。超过上限 50 步时丢弃最老
  状态（`_h_index` 相应左移）。checkpoint 后 `_redo` 天然清空
  （尾巴已截断）。置 `dirty = True` 的职责仍在原有路径，不在
  这里重复。
- `undo() -> bool` / `redo() -> bool`：移动 `_h_index` 并以
  `Widget.from_dict` 重建 `roots`；成功返回 True。重建后
  `dirty = True`（与存盘状态可能不同，宁可多提醒保存）。
- `can_undo` / `can_redo` 属性给菜单置灰用。
- 快照必须深拷贝：`to_dicts()` 本就逐层新建 dict（Widget.to_dict
  递归），但属性值含 list/tuple（如 `lNormalColor`），恢复时
  `from_dict` 也会复制；checkpoint 仍做一次 `copy.deepcopy` 兜底，
  防止就地修改列表绕过快照。

### 1.3 合并规则（哪些连续动作算一步）

| 来源 | 提交点 | 合并键 | 效果 |
| --- | --- | --- | --- |
| 属性面板改单个字段 | `changed` 信号 | `("prop", id(控件), 字段名)` | 连续打字/连续拨数值只算一步 |
| 画布拖动/缩放 | 鼠标释放（新增提交回调） | 无（释放即一步） | 一次拖放算一步 |
| 加/删/重排/提升控件 | 主窗口各操作方法尾 | 无 | 各算一步 |
| 选图改图片/音频字段 | 属性面板路径 | 同属性面板规则 | 一步 |

注意：拖动过程中 `itemChange` 只改模型与 dirty，**不**进历史；
`WidgetItem` 需新增“几何已提交”回调：在按下时记住几何，
`mouseReleaseEvent` 若几何变化则通知场景 → 主窗口 checkpoint。
缩放手柄走同一 mouseRelease 路径。

### 1.4 选择恢复

恢复会重建全部 Widget 对象，旧选中指针失效。主窗口在撤销/重做
前记录当前选中控件的**根序号路径**（如 `[0, 2, 1]` = 第 0 个
顶层 → 其第 2 个子 → 其第 1 个子），恢复后按路径重新解析选中；
路径越界（控件已被撤销掉）则清空选择。属性面板、控件树、画布
走既有 `_select_widget` + `_refresh_structure` 刷新。

### 1.5 UI 接入

- 菜单新增「编辑」菜单：撤销 Ctrl+Z、重做 Ctrl+Y（兼容
  Ctrl+Shift+Z），按 `can_undo/can_redo` 置灰；每次
  checkpoint/undo/redo 后统一刷新置灰状态。
- 工具条不加（菜单+快捷键足够，避免挤占画布空间）。
- 打开/新建/从包打开布局成功后 `reset_history()`；保存成功
  **不**清历史（存盘后仍可撤销回改前状态，dirty 再亮）。

### 1.6 验收

自动测试：
1. 一串操作（加控件、改属性、删控件）后逐级 undo 回到打开时
   状态，`to_dicts()` 与初始逐字相等；再逐级 redo 全部回来。
2. 拖动手柄式连续属性改 5 次同字段 → 历史只多一步（合并）。
3. undo 后做新编辑 → redo 尾巴清空，redo 不可用。
4. 超过 50 步只保留最新 50，仍可退到第 50 步前一状态。
5. 撤销删控件后按原序号路径恢复选择（GUI 层测试）。

手工验收：在真实布局里拖、删、改十几步，一路 Ctrl+Z 回原样，
保存后文件与回滚结果一致。

### 1.7 不做

- 跨文档历史、历史持久化（关程序即弃）、按操作命名的历史面板
  （将来想要再加，数据结构已支持命名扩展）。

## 2. M3 像素级绘制（0.5.x，分三个小步）

### 2.1 M3.1 画布导航与吸附（先做，纯 UI 层）

- 缩放：`QGraphicsView` 已有 fit/100% 两个动作，补 Ctrl+滚轮
  以鼠标为中心缩放（10%–800%），状态栏显示当前倍率；空格+拖动
  或中键拖动平移（ScrollHandDrag 切换）。
- 网格与标尺：可选显示 1px/10px 网格（视图菜单开关，默认关）；
  标尺画在 scene 边界内侧，成本低优先做简化版（顶部/左侧刻度
  条跟随缩放重绘）。
- 吸附：拖动时对齐其他控件的边缘与中心线（阈值 6 屏幕像素），
  显示品红参考线；Alt 拖动临时禁吸附。吸附计算放 `core/` 写
  纯函数（输入全部同级控件矩形+被拖矩形，输出修正后坐标与
  命中的参考线），好测。
- 对齐/分布：工具栏小按钮组：左/水平中/右、上/垂直中/下对齐
  （以第一个选中或父容器为基准，第一版只做“相对父容器”与
  “相对首个选中”两种），三控件以上可等间距分布。对齐以
  **同级多选**为前提 → 画布需支持 Ctrl+点击多选：第一版只开放
  “全选同级+对齐到父容器”的弱化版，多选做完再升级（见 2.4）。

验收：纯函数单测（吸附命中/不命中/多候选取最近）；手工在真
实布局里把按钮拖到与邻居对齐，保存回游戏位置正确。

### 2.2 M3.2 按钮多状态贴图

数据摸底（动手前做，半日量）：按钮的样式来自
`core/styles.py` 语料统计出的 style 家族（`sFileName` 单图 +
`lNormalColor` 等），真实按钮图有两种流派：

- 单张图，游戏靠 `styles` 里的切割参数画不同状态；
- 多字段分别指向不同图片（需全语料找带 state 字段的按钮样本）。

设计先定**不依赖未摸清部分**的形态：
- 属性面板对图片字段增加状态预览切换（正常/按下/悬停 三个
  画布预览模式菜单项），画布按 `painters` 的既有样式逻辑渲染；
- 摸底确认存在“多字段分状态”的流派后，再给这些字段配成套
  编辑（一键套用同目录同名 -down/-over 变体）。

验收：至少各取一个 dialog4/ 现役按钮样本，编辑器内三态预览
与游戏截图肉眼一致。

### 2.3 M3.3 九宫格

- 数据：九宫格切割线不在 .dlg 通用字段里（需 2.2 同期摸底：
  查 style 定义与图片命名习惯，确认切割参数存哪——候选是
  `core/styles.py` 的样式表或图片旁的命名约定）。
- 编辑：图片字段旁加“九宫格…”按钮，弹出切割线编辑器（图上
  四条可拖的线，数值同步），保存为该字段的切割参数；若摸底
  结论是“游戏不支持逐图切割、只有固定样式”，则降级为仅按
  样式表预览，不硬造字段（**把游戏读不懂的数据写进 .dlg 是
  红线**，与写回包的校验原则一致）。
- 画布：`painters` 对带九宫格的图按四角固定、边单向拉伸、
  中心平铺渲染；与现有效果对比验收。

### 2.4 顺序与依赖

```text
M2 撤销/重做 ──► M3.1 吸附/对齐（多选弱版） ──► M3.2 按钮多状态
                                          └──► M3.3 九宫格（依赖 2.2/2.3 数据摸底）
```

M3.2/M3.3 开工前各做一次小摸底（语料统计脚本落 `tools/`），
摸底结论若推翻设计假设，先改本文再动手。

## 3. 风险与红线

1. **撤销后保存**：快照恢复出的文档照样走现有写回硬校验，
   不一致会被拦下——撤销功能不得绕过任何校验路径。
2. **未知字段**：.dlg 的未知属性在 `to_dicts/from_dict` 往返中
   必须无损（既有约束，M2 快照正好压力测试了这一点）。
3. **性能**：checkpoint 是整文档深拷贝；语料内最大布局先做一
   次计时，单次超过 50ms 再优化（增量快照不在本期）。
4. **不新增写回格式知识以外的猜测**：九宫格/多状态凡涉及往
   .dlg 写新字段，先以真实样本验证游戏能读，再落实现。
