# M2 原生新包核心（0.2.0.dev1）

## 实现与安全边界

这是独立工具的**实验后端**，不是解压即用Windows发行包。GUI仍禁用写包，M3再接入。
`core/services/native_build.py:build_package`接受明确下标、条目身份和自写标准pyc，
要求源包SHA256与精确版本编译器；不自动导入游戏模块、不自动新增可导入条目。
源码业务是否正确/是否与条目对应仍须人工确认。

每次构建：

1. 检查源包指纹、候选VM、下标/身份、非目录、不重复；标准pyc经对应标准CPython完整marshal读取，
   不执行目标。CLI还要求明确确认可信源码来源，反编译参考稿不能自动升级。
2. 修改目标的**原条目**必须能严格识别。原包未知格式/损坏/缺键直接拒绝，未改条目仅按存储字节复制，
   不要求把其它所有游戏模块解码成功。
3. VM2.5：递归marshal中所有co_code做等宽映射；外部catalog必须同时绑定包SHA、catalog SHA、
   下标、身份、存储负载SHA。沿用固定五段边界和原扩展长度，小载荷根对象后仅填零；大于原长度拒绝，
   不裁lnotab、不缩放边界、不猜修opcode。之后XOR、zlib。
4. VM2.7：递归加co_extra与分离指令/参数流；相对/绝对跳转的指令与参数**两个**坐标均计算并校验。
   末尾只加/去一个NOP哨兵，不能吞掉真实NOP；行号转指令索引，保留合法零行差事件。
   只聚合`255,0`溢出片段，不能把同一行分号产生的`6,0`等事件一概删掉。
5. 临时写包：0SLF目录保持原ID/下标/r1，按原物理负载顺序保存（真实包物理顺序与目录不同）；
   保留头的未知字段、空隙与尾随字节。data FLS保留头、原编码文件名/目录标志；未改本地记录连同填充
   逐段复制，改项重压缩并重算CRC/长度/偏移，保留其原填充。
6. 重新打开临时包，全量比较身份/元数据与未改条目（分块比较）；比较容器头/空隙/填充/尾部。
   改项从**实际新包**解压/解密/解析，独立逆变换后的整个标准marshal必须与新编译结果逐字节一致；
   再由精确版本CPython完整marshal读取并检查EOF。共享marshal语法树不取代这一独立运行时读取。
   VM2.5原生无pyc头，回读头使用本次已知标准头，不宣称原生存有时间戳。
7. 源包没有变化后，以同目录临时文件硬链接原子发布新名字。**任何已有目标都拒绝覆盖**，包括旧输出、
   原包及其别名；发布竞态出现的新文件也不覆盖。文件系统不支持硬链接则失败，不退化为覆盖写。
   失败清理临时文件，原包不动；每次重建请选一个新名字。Windows/非NTFS行为仍待实测。

## 明确拒绝的情况

- VM2.5载荷比原扩展长度大；缺失或不匹配的外部XOR来源。
- 不能无猜测读取的原模块。当前锁定原包条目337即会因未知opcode被拒绝；不要拿旧工具修复当成功。
- VM2.7 EXTENDED_ARG、指令/参数寻址超uint16、非边界跳转、双坐标不一致、无法全字节回读的行号表。
- 未知marshal标签/过深嵌套/不合法引用；变换的co_code/lnotab非原始`s`字串（不猜测intern引用的修改语义）。
- 单条解压/marshal超64MiB、截断/拼接压缩流；data改项不是raw-deflate方法8或原CRC不符。
- 任意恢复游戏代码的运行。此工具只是离线编译、转换、数据解析，不是安全沙箱；只编译自己确认的源码。

## 证据不是往返自证

新增手工黄金字节覆盖跳转双坐标、NOP、opcode语义，以及真实标准2.5.6/2.7.13编译/完整marshal回读。
历史VM2.7注释把Python2.5名称/编号混用，当前DLL实际分发表为RVA `0x12D8EC/0x12DA94`，
不是旧笔记地址。关键操作的语义重新静态核对：

| 标准2.7编号/语义 | 原生opcode |
|---|---|
| 104 BUILD_SET | 183 |
| 105 BUILD_MAP | 137 |
| 106 LOAD_ATTR | 230 |
| 107 COMPARE_OP | 124 |
| 108 IMPORT_NAME | 135 |
| 109 IMPORT_FROM | 155 |

opcode66在当前DLL走未知指令处理，不是旧表所称STORE_SLICE别名，已排除。
只读样证据`tests/evidence/py27_dispatch.json`钉DLL SHA、分发表、处理器地址/片段；
独立标准库PE读取测试不加载DLL。旧研究工具/证据指纹未改。

## 实验命令行

在工具目录中：

```sh
PYTHONPATH=src python -m script_editor.native_cli --help
```

必须显式提供以下参数（没有隐式全仓库搜索或默认编译器）：

- `--archive` / `--archive-sha256`：源包及当前精确SHA。
- `--entry-index` / `--entry-identity`：明确目标；0SLF身份是8位大写hex，data是原目录中的完整名字。
- `--source` / `--module-filename`：UTF8真实源码，以及原模块嵌入文件名（明确指定，不猜导入名）。
- `--compiler` / `--vm py25|py27`：对应标准编译器完整路径。
- VM2.5另需`--keys` / `--keys-sha256`：与源包匹配的外部研究catalog；不会内置复制游戏键表。
- `--output`：现有目录内**尚不存在**的`.fls`。
- `--confirm-authored-source`：显式确认来源，否则拒绝构建。

构建成功只打印ASCII-safe JSON报告，包括输入/输出SHA、所选替换下标、其余条目数。
不代表游戏可正常加载/注册服务器可用；若要用于游戏，仍须在测试副本做原生实机验收。
实验CLI一次只接一个源码模块；核心API支持明确的替换集合，项目续编/差异列表留给M3。

## 本轮实测

- 真实标准CPython 2.5.6/2.7.13，含嵌套代码、闭包、导入、属性/比较、切片、集合/字典、复数/long、
  大跨度行号和同一行分号；故意包含写文件/raise的目标源码未执行。
- 原始script.fls仅替换4007为现有自写注册源码，另5001条存储字节全等；原始data.fls用75作离线探针，
  另132条本地记录全等。**data探针有意替换核心库，绝不能用于客户端。** 所有产物在仓库外或测试临时目录。
- 79项收集，73通过、6 GUI因缺libGL未执行；ruff/wincompat零报告。CLI真实data离线链跑通。
- GUI/Windows/EXE/随包运行时均未验；这不覆盖所有原模块、所有Python2语法或原生游戏兼容性。
