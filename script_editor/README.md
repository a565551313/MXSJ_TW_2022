# MXSJ 独立脚本编辑器 0.5.1.dev1（包内恢复编辑源码测试版）

**独立源码测试包，已补齐两套 Windows x86 标准编译器；用户可自行构建 EXE。**
Windows 桌面、编译器实际启动和客户端加载仍需实机验证，未标为验收完成。
不是已验收的 Windows 发行版，也不保证任意原始模块都可编辑。
本目录可以独立复制，不在运行时导入 UI/资源编辑器或仓库 `tools`。
源码GUI支持Python 3.10—3.14，固定PySide6==6.10.3；核心不依赖Qt。

## 0.5.1 修复Python3.14启动失败

0.5.0固定xdis6.1.8仅允许Python<3.13，却声明GUI支持3.14，是本工具的依赖兼容错误，不是用户网络问题。
旧uncompyle6还限制xdis<6.2；新版使用上游已支持3.14的固定源码提交（3.9.4.dev0）＋xdis6.3.0，
完整源码随包、安装前核SHA，不忽略Requires-Python、不伪改上游依赖。详情见[源码来源](third_party/README.md)。
无需更换/降级你的Python3.14；启动器自动安装包内源码和匹配依赖。
Qt是开窗必需项；恢复引擎安装失败不再拦住整个界面，但完整自检/发行检查仍失败，不假报恢复可用。
实际Python3.14.7完成pip依赖安装、启动器自动补装及二次启动不重复安装、pip check，
且181/181（32 GUI）通过；Python3.11同套181/181通过。这是Linux主机结果，非Windows/EXE/客户端实测。

新版还修正集合常量恢复：旧引擎有把列表实际值误写成常量下标的问题，新版已测列表/字典值及256字节保真。
**保留你已有.py和项目副本，不要覆盖修改；旧0.5.0恢复稿建议重新从原包恢复后对比合并并核验，不要直接当原源码。**
新引擎正确恢复的register4007回编超过固定容量49字节，仍拒绝；不会为过容量继续用错误常量或裁lnotab。
真实容量内回包回归改用script4001（明确缩短展示文字）和data75，4007另测正确恢复与安全拒绝。

## 0.5 包内读取与恢复编辑（不宣称所有模块均已支持）

用户指出0.4只会关联外部源码，不能打开现有条目：这是产品核心缺口，不是用户缺源码。
本轮双击未关联条目会后台严格解码，再交独立恢复进程生成源码工作草稿、反汇编与模块信息；
不再统一要求“先打开自己的源码”。恢复草稿可编辑、撤销、查找及另存UTF-8；
已有外部“只读参考”仍只读，不会悄悄提升来源身份。

工作流：
1. 打开script/data，双击条目。data按独立VM2.7解码；script仍需匹配原包的五段XOR参数目录。
   **已获授权附带固定原包匹配表，后台完整SHA匹配并核对参数摘要后自动启用，不再要求手动找JSON。**
   其他包不会套用；此前生成的派生包请打开对应项目续编，或显式确认参数来源。见[匹配范围](decoding/README.md)。
   未知opcode/坏CRC/不支持格式/缺参数显示具体失败及存储预览，不造pass占位脚本。
2. 在“恢复草稿”直接修改，可切换反汇编/来源信息。草稿不是原始源码，不自动绑定/写包；
   Ctrl+S首次必须另存新.py，拒绝覆盖及竞态覆盖。重新打开有草稿标识的文件仍可编辑且未核验。
3. “检查并采用为源码…”：检查条目/VM/包指纹、真实标准编译、原生转换和完整回读；
   全过后还须人工核对逻辑并明确采用。记录`recovered-reviewed`及原标准字节码SHA，
   项目重开也保留来源，不假称原始源码。部分恢复的原样输出不准直接采用，须先修复。
4. F6预编译清单，再选新包输出；未改条目逐条保持、旧包只读、项目承接新包流程不变。
   编译/回读通过不能证明反编译业务逻辑一致，仍须用户核对及客户端验收。

独立恢复程序使用uncompyle6/xdis/spark-parser等固定版本，只读取标准pyc数据，不import/exec目标。
GUI进程不导入恢复引擎；工作进程30秒超时、输入marshal/输出大小受限。
修正其Unicode字面量显示（中文/引号/反斜杠/非BMP）、Py2.5不支持的b前缀及非法模块末尾return，
均为文本输出适配，不修改opcode、编译器或原有五段边界，不整文件转码。
GPL工作进程与主GUI分开构建，完整许可证/源码交付方式见[恢复引擎许可](licenses/recovery/README.md)。
Windows构建新增独立EXE实际双VM smoke，不通过就阻断；本轮尚未Windows构建/执行。

已新增真实双VM无源打开→恢复编辑→编译→新包→回读→项目再开的核心与Qt测试。
真实原包script下标4001、data75的隔离恢复/编辑/新包回读也通过，不执行模块、不交付测试游戏包。
**仍非任意模块全面可编辑**：未知映射/失败反编译保留诊断；script超出原展开长度仍拒绝。
0.5.1正确恢复4007原样回编超固定容量49字节，不能直接写回；
容量内改动回归用script4001缩短展示文字验证，不代表任意增长，不裁lnotab、不缩放边界。
本次为含新核心流程的独立源码测试版，不用旧0.4.1包冒充；请完整解压到新目录。

## 0.4.1 修复Windows刚打开就报“源包变化”

0.4.0混用了`stat(path)`与`fstat(fd)`的修订信息；部分Windows CPython中，前者的ctime
仍兼容创建时间，后者是实际变更时间，同一文件会被误报。现在重新打开路径并统一使用fstat，
同时核对原句柄与新句柄的身份、大小、修改/变更时间，未关闭真正的源包变化/路径替换保护。
初始修订与读取大小一次捕获，防止解析前变化被重新当作基线；临时核对句柄始终关闭。
请用新目录解压0.4.1，不再反复尝试0.4.0。此修复已做模拟Windows差异回归和Linux实测，
尚需用户Windows实机确认，不把模拟测试当作Windows执行证据。

## 0.4 工作区重整（独立源码测试版）

不再用菜单＋三栏文本框作为完整编辑器：常用工具栏与菜单共用真实动作；
包选择器切换script/data独立导航，显示下标与原始身份；中央多标签源码工作区，
右侧来源/状态及可跳转的类/函数大纲；底部独立诊断、布局/控件引用和源码差异。
面板可停靠、隐藏、恢复，正式入口记忆窗口布局，不自动打开游戏文件。

- Ctrl+F查找/替换支持区分大小写、整词、前后循环定位和一次撤销的全部替换。
- 编辑区增加等宽字体、当前行、四空格Tab/选区缩进和自动缩进，参考稿仍只读。
- 引用与大纲只做词法静态线索，不执行源码、不冒充语法或挂载验证。
- 差异明确对比“打开时源码/当前缓冲区”，不伪造原包源码基线。大型源码暂停自动分析。
- 用真实Qt依赖跑GUI回归，大包节点风险不再只靠几个玩具节点测试：6000节点专项回归。
  PySide6 6.12.0在本机Python3.11.2上已复现QTreeWidgetItem构建时None引用计数损坏/崩溃；
  已固定并验证6.10.3，bootstrap修复版本不符依赖，直接GUI入口拒绝其它Qt版本。
  菜单及其QAction保留强引用，防止枚举菜单动作后C++对象被释放。

这是主工作区第一轮重整，不代表任意游戏模块均能恢复可信源码或Windows实机验收完成。
已上传的0.4.1.dev1源码包包含0.4界面及开包修复和两套Windows编译器，尚不含0.5恢复编辑；旧0.3.2不包含。
请完整解压到新目录，不覆盖旧工具或游戏目录。

## 当前具备什么

- 同时打开 `script.fls`（0SLF）和 `data.fls`（FLS\0）的只读索引，区分包来源、候选 VM、
  条目下标与稳定身份；支持 ID/路径筛选、目录项标识与元数据查看。
- **容器识别不等于验证内容是脚本。** 同头的美术包也可能被识别为0SLF；界面明确标候选VM。
  双击严格校验并恢复可编辑草稿；草稿不会自动获得已核验源码身份；
  不猜测条目名，也不套 `.dlg` 路径哈希作为导入规则。
- 手工确认来源的 UTF-8 源码，多标签、行号、含多行字符串的高亮、查找、替换全部、撤销/重做、脏标记与关闭提醒。
  参考稿可单独只读打开，禁止保存、修改、关联和编译；不把反编译稿自动升级为可信源码。
- 原子保存源码；源码保存与生成包分离。UTF-8 BOM可读，保存为无BOM的UTF-8；不保持原CRLF/BOM。
- 显式将选中的**文字内容**转换为 Big5 文案或 GBK 路径的转义字节字面量；转换前预览确认。
  选择中不要包含引号/`u`前缀；不可编码直接报错，不替换丢字、不整文件转码。
- `.mxscript.json` 保存**用户手工关联**的包 SHA256、VM、条目下标/身份、源码相对路径；
  schema2另存原嵌入文件名HEX、上次成功入包源码SHA与显式XOR目录的路径/摘要（不复制keys）。
  兼容schema1读取；不复制包/源码、不保存凭据/编译器路径。打开项目严格复核指纹/身份。
  打开后源包原位变化或同路径替换也拒绝使用旧索引；SHA按需读取并缓存，不解压条目。
- 两套独立标准编译入口：`script → CPython 2.5.6 / b3f20d0a`，
  `data → CPython 2.7.13 / 03f30d0a`。检查精确版本、魔数、位数、exe SHA256；Windows要求x86。
  子进程 `-E -S`，不改PATH，不加载游戏模块，30秒超时；先临时编译再原子发布标准 `.pyc`。
  编译用当前编辑缓冲区，无需先保存。失败保留旧输出，禁止覆盖输入和已知别名。

**GUI的“仅编译”只得到标准 `.pyc`，不能直接塞进 FLS。**
M2另提供受限API/实验命令行：确定性双VM转换 → 临时新包 → 全量逐条/独立逆变换校验 →
完整CPython marshal读取 → 不覆盖现有文件的原子发布。详见[原生构建说明](M2_NATIVE_BUILD.md)。
M3将此后端接入GUI：快照预编译→不可变清单→明确单条替换→新包承接→项目续编。
详见[M3工作流与限制](M3_WORKFLOW.md)。源码业务语义仍由用户确认，不把离线通过冒充游戏验收。

## 启动

Windows 源码目录双击 `启动脚本编辑器.bat`，或：

```sh
python bootstrap.py
python bootstrap.py --check-only
```

自检会补安装 Python3 GUI依赖（固定PySide6 6.10.3），并在官方源失败时提供镜像回退。
已安装PySide6但缺系统Qt动态库时会明确失败并写`启动日志.txt`，不会假报GUI就绪。
`--check-only`现在检查GUI加载、两套编译器精确版本/魔数、真实编译及完整marshal回读，失败返回2。
也可双击`检查内置编译器.bat`，仅检查双编译器而不安装GUI依赖；检查不执行目标源码。
这些检查不等于客户端游戏验收。

开发环境也可以安装本目录后运行 `mxsj-script-editor`，或：

```sh
PYTHONPATH=src python -m script_editor
PYTHONPATH=src python -m script_editor --version
```

1. 文件 → 打开脚本包索引；同一窗口可同时挂两个包。
2. 双击条目，直接读取/恢复草稿，不需外部.py。编辑后“检查并采用为源码…”按顶部工作流核验。
   也可打开自己确认来源的UTF-8源码；来源确认选“否”则只读参考，不可编译。
3. 核对VM、条目及来源，保存项目用于下次续编。
   项目保存仅保存关联，**不会代替源码保存**。源码/包/项目同一盘时可相对路径整体迁移。
4. 启动会在后台检查两套内置编译器；诊断区应显示2/2可用，无需安装Python2或手动选EXE。
   可在编译菜单重新检查；“仅编译为标准.pyc”只输出标准字节码。
   标准.pyc单独导出仍使用源码路径UTF-8字节；native构建保留原模块嵌入文件名原始bytes。
5. 固定原包自动匹配内置参数，其他script包须显式核实参数。采用/关联源码后使用“生成原生新包：预编译与清单”，
   通过后确认输出到新名字；成功自动承接新包，编辑区未保存文字与撤销保持。
   请另存源码/项目；取消、预编译或发布失败不自动保存源码。只有SHA没有旧源码文本时不伪造逐行diff。

## 内置双编译器

- `runtimes/py25/win-x86`：CPython 2.5.6，标准魔数`b3f20d0a`，用于script。
- `runtimes/py27/win-x86`：CPython 2.7.13，标准魔数`03f30d0a`，用于data。
- 每套包含真实x86 `python.exe`、对应DLL、ZIP_STORED纯Python标准库、5份许可与BUILD.json。
  schema2清单包含全部18个运行时文件的实际SHA256、官方源码URL/commit/归档SHA。
- 面向Windows 10/11，依赖操作系统UCRT和系统DLL，不支持XP/Win7；没有打包微软CRT或游戏DLL。
  是源码编译/marshal用途的最小运行时，不是含全部外部扩展的通用Python2发行版。
- 官方源码交叉构建，只有MinGW平台适配；compiler/opcode/marshal实现未改。
  `build_runtimes.py`供维护者从固定来源重建，不是普通启动或构建EXE的前置操作。
- 整套文件SHA/PE32/来源许可检查在注册、编译、回读前后复核；不回退系统Python/PATH。
  缺件/篡改/版本错误会禁用相应编译入口。Git不存放这些生成的二进制，完整源码交付ZIP中包含。

已完成真实PE构建及静态清单审计；**尚未在真实Windows执行，不宣称桌面/EXE/客户端验收通过。**
详见[运行时构建记录与剩余实机检查](M4_RUNTIME_DISTRIBUTION.md)。
