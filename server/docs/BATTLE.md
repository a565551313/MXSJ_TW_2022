# 战斗与其他模块的交接契约

## 证据与设计分开

客户端 entry 1406 `netwar.py` 的攻击/技能请求与血量变化回包、entry 697 `core/war.py` 的指令表现已作函数级抽查。
这证明存在“客户端请求 → 服务端结果 → 客户端表现”的边界，不证明原版回合算法或完整伤害公式已恢复。
下列阶段是我们提出的框架，不声称原服务器采用相同结构。

## 生命周期

`PREPARING → COLLECTING → LOCKED → RESOLVING → PRESENTING → 下一回合或 SETTLING → CLOSED`

- 战斗实例管理者是唯一写入者。超时、玩家输入、离线托管都进入该实例队列。
- 行动包含 battle_id、round_no、actor_unit_id，验证操控权与角色/宠物出战关系。
- 同一单位同一回合是否允许改令由规则确定；第一版不得自行假定。锁定后明确拒绝修改。
- 等待输入不持有数据库事务。表现ACK不决定胜负，且有服务器最大等待期限。
- 掉线不删除战斗；重新认证并完成session epoch切换后，返回 BattleView。
- BattleView不得泄漏敌方未提交/未公开行动、随机种子和完整隐藏属性。

## 跨组必须共同冻结的内部接口（起步公开API之外）

| 交接 | 提供方 → 消费方 | 数据与约束 |
|---|---|---|
| StartBattle | 世界/任务/活动 → 战斗 | 场景、模式、参与者ID、可信遭遇配置、operation_id；拒绝重复建战 |
| CombatantSnapshot | 角色/宠物/子女 → 战斗 | 属性、装备/技能快照、实体版本、固定配置版本；只读副本 |
| BattleOwnership | 角色运行时 ↔ 战斗 | 状态从世界切换到战斗，阻止同一角色同时进入两场；失败补偿必须幂等 |
| ResolveRound | 战斗 → 技能/规则 | 状态快照、已锁定指令、显式随机状态、规则版本；无网络/数据库副作用 |
| ReserveConsumables | 战斗 ↔ 资产 | 药品等需防止战斗使用与交易同时消费；预留/消费/释放的唯一键明确 |
| RoundResolved | 规则 → 战斗 → 协议 | 有序事件、新状态、回合号；协议层转换为客户端可播放结果 |
| SettleBattle | 战斗 → 奖励协调 | 不可变结果ID与资格，奖励由服务器配置生成；同结果同角色仅落账一次 |
| ResumeWorld | 战斗 → 世界/角色 | 结算完成或明确中断后恢复；不得同时在地图和战斗两处自由写入 |

这些内部载荷需要 E/B/F/C/D/G 组联合审阅，当前没有用 `dict[str, Any]` 假装所有细节已解决。

## 计算核心目标

```text
resolve_round(state, locked_commands, ruleset, rng_state)
    -> new_state, ordered_events, new_rng_state, outcome
```

- 规则函数不读系统时间、不读数据库、不调用全局随机源。
- 固定遍历与同速排序规则；随机消耗顺序属于版本化规则。
- Buff生命周期、触发顺序、取消/反击/连击等必须作为明确规则，不隐含于动画。
- 客户端 skill/effect 资源可能描述表现，不能不经核实当成服务端效果规则。

## 恢复与结算

建议第一版以回合边界持久化快照，记录被确认接受的输入及系统超时输入；存代码/配置/快照schema版本和随机状态。
落地前必须明确“指令确认何时持久化、回合结果何时持久化、崩溃后恢复到哪一阶段”。不要只记录种子后宣称支持恢复。

结算至少有 `pending/committed/failed_retryable` 状态。发送结果失败不回滚已提交资产，重连按结果ID查询。
进程恢复无法继续某场战斗时，按明确中断规则释放预留资产；不可静默发奖或清空全部战斗。

## 战斗组验收

固定输入可复现；迟到指令、重复提交、超时与命令同时到达、旧连接写入、断线回归、结算重试、消费与交易冲突、配置升级后的旧战斗均有测试。
内部规则可在没有客户端和数据库时跑测试；持久化恢复必须用真实数据库集成测试。

## 网关拆分兼容约束

遵循 [GATEWAY.md](GATEWAY.md)：战斗实例不属于网关，网关失联不删除战斗。
客户端行动经会话校验后按 battle_id 路由，实例在接受边界校验 session_epoch、操控权、回合与锁定阶段；
实例归属迁移另用 owner_epoch，不与会话接管代数混淆。
同一回合指令的幂等/改令规则仍须冻结，不把重新投递自动当作允许改令。
回合结果返回类型化事件/授权视图，由回送层处理当前连接；不把 socket 或发送回调保存进战斗快照。
重连先验证会话再取得 BattleView；推送失败不重算已结算回合，不重复发奖，也不泄露随机状态/敌方未公开行动。
