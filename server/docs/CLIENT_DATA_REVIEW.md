# 客户端静态配置：异常复核与处理顺序

日期：2026-10-11。对象是**道具、宠物的静态列表**，不是玩家实例。

## 当前结论

先修复、验证提取链路，再制作正式 CSV。不要手填猜测值，也不要把所有表的差异都当作损坏。
本轮已经取得四个可复现的边界修复候选，但没有修改客户端、原 FLS、旧密钥数据库或原反编译器；没有将任何候选写入 `game_data/`。

“候选”不等于已通过原生客户端验证。尤其文字通顺、编码合法、字典能构造，都不能单独证明原文完全正确。

## 复现

从仓库根目录运行（仅标准库；不执行还原出的游戏脚本）：

```bash
PYTHONDONTWRITEBYTECODE=1 python3 server/tools/review_client_data_boundaries.py
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s server/tests/architecture -v
```

机器可读结果：[client_data_boundary_review.json](catalog/client_data_boundary_review.json)。包含原始 FLS 与密钥库 SHA-256、原始异常字节、候选边界、前后值、局限与失败记录。

工具复用已有转译器和 marshal 读取器，用有限指令白名单重建字面量表。遇到调用、导入、跳转、重复键等情况拒绝构造目标表。原有转译器本身含启发式修复，因此整个输出仍是研究材料，而不是经过原生加载器认证的数据。

## 已定位的四个候选

偏移均为 zlib 解压后、XOR 解混淆前载荷中的零基偏移；不是 FLS 文件偏移。每次探测只改一个边界，分别与基线比较，没有将所有候选合并成发布版本。

| 条目/记录 | 保存的边界 → 候选边界 | 探测结果 | 验证边界 |
|---|---|---|---|
| 1945 / 道具10424 | 259624 → 259583 | “同心靈果·陰”描述的后半段恢复为连贯文本 | 局部扫描仍有其他可严格解码的候选，不能仅靠编码合法性定案 |
| 1945 / 道具71700 | 1038363 → 1038307 | “時空之輪”的使用条件、迷宫名称恢复为连贯文本 | 同样存在多个可解码候选，需要独立证据 |
| 1115 / 宠物2910 | 825 → 828 | 整数2280变为“混沌騎士”，与2027表同标识名称相符 | 探测时关闭字节码边界自动求解，防止启发式覆盖指定边界；不是已验证通用修复 |
| 2242 / 列表索引16 | 262 → 264 | 数值64605变为416，邻项是415、417 | 连续编号只作辅助证据，仍须与技能主表/客户端加载结果交叉核对 |

四个探测分别只改变其目标表中的一条记录，记录总数均未改变。这里只比较指定目标表，不代表整个脚本的所有常量、代码均已验证。

## 仍未解决，不得悄悄删除或猜值

- **道具72548名称**：当前字节可读前缀为“雙人坐騎體驗”，末尾是无法严格按CP950解码的 `84`。位于载荷偏移1100465，不邻近已保存的四个XOR边界。不能简单剪掉末尾就声称已恢复完整名称。
- **宠物2027表的两个嵌套字段**：本轮递归检查发现2600的 `address`、4011的 `maySkillLst[3]` 也有严格CP950错误。此前只确认了宠物名称可解码，不能因此认定整张详细表已干净。
- **宠物技能主表3205**：依旧无法可靠构造；更严格的指令扫描现在先发现异常的 `EXTENDED_ARG` 序列。之前的常量索引越界是另一解析路径遇到的症状，不应当作客户端运行时报错。
- **道具扩展1698表**：存在不可解码文本及可解码但可疑的文字；未完成修复。
- 其他能解码的文本、数值仍可能有错误。这里列的是已发现的问题，不是完整的异常总数。

## 两张宠物表不能盲目合并

- `petdata`详细表135条，`mxpetdata`映射表137条，后者多5106、5107。
- 同一标识4024分别写“仙獸雷吉斯”和“神獸雷吉斯”。没有证据应直接统一名称。
- 使用保存的密钥和边界对5002个条目作 `mxpetdata` 字面字节串搜索，仅匹配1115条目本身。**这不证明该表无用**：动态导入、原生代码访问、解码偏差都可能造成漏检。具体调用用途仍未确认。
- 因此保留两份来源，不以137条表覆盖135条表，也不因条数不同认定客户端损坏。

## 后续实施顺序与验收条件

1. **保留证据与隔离**：原始字节、来源条目、原ID、解码版本和异常原因必须可追溯。研究结果留在本目录，不进入运行时静态配置。
2. **验证提取器**：优先追踪原生加载器的真实分段算法；或者取得相同版本客户端显示/独立读取结果交叉核对。不能把“中文看着正常”变成通用自动修复规则。
3. **完整校验目标表**：递归检查编码和字段类型，验证ID唯一性、宠物技能引用、图片映射与客户端回退规则；明确列表包含的测试/历史记录。不能只检查名称。
4. **导出待审CSV**：保留原ID和原字段，多值技能另表存放；异常记录独立隔离。工具生成结果与人工修改必须分开，不允许静默覆盖。
5. **发布正式配置**：完成审核、引用闭合、版本与校验和后才进入 `game_data/`；客户端展示文案不能代替服务端权威数值规则。

本轮新增8项研究回归测试，与原17项架构检查共25项通过。它们证明复现一致、输入未被工具改写、候选没有被标成正式数据，以及已知问题没有被隐藏；**不证明候选已与真实客户端运行结果完全一致**。
