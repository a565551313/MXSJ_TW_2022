# 多功能网关：安全防护与 GM 控制面 v0.1

日期：2026-10-12。状态：**设计已纳入基线，安全设施、GM API 和控制台均未实现**。
本文件补充 [GATEWAY.md](GATEWAY.md)，不替代其会话、路由、幂等和恢复语义。
新服务端设计，不从客户端 GM 脚本推断服务端权限，也不表示已还原原版反作弊系统。

## 1. 决策：统一网关产品，隔离三类入口

多功能不等于一个可以执行任意命令的超级进程。共享配置版本、可观测性和接入基础设施，
但公网游戏入口、GM 控制面、内部服务入口使用不同监听、协议白名单、身份体系与资源预算。

```text
玩家客户端 → 公网游戏入口 → 安全策略/会话/路由 → 角色、世界、战斗等业务拥有者

GM 控制台 → 私有管理入口 → 管理员身份/MFA/权限/审批
                                      ↓
                           administration 管理用例
                                      ↓
                           对应业务端口 / 安全策略控制
                                      ↓
                           幂等结果 + 审计/outbox

内部服务 → 服务身份认证入口 → 内部消息白名单 → 被授权的内部端口
```

- **公网游戏监听绝不注册 GM 路由/opcode**。玩家票据不能兑换管理员权限；source=admin 不能由请求自行声明。
- GM 是同一网关产品的管理能力，但不是开放在玩家端口的后门；GM 控制台可以独立开发/部署。
- 第一版允许同进程独立监听，必须隔离连接池、队列、并发和限流配额；这不是进程级故障隔离。
  独立部署时管理入口应放在独立进程/受限网络，避免游戏入口被攻击时管理通道一同失效。
- 生产 GM 不对公网直接开放：经 VPN/受控接入代理或等效私有网络到达，仍须应用层认证和授权。
  不依赖“隐藏 URL”、CORS、IP 白名单或只绑定某个端口作为唯一保护。
- 管理和内部连接使用 TLS；内部使用可验证的服务身份。玩家旧协议的加密兼容须核查并按需改客户端，
  不自创加密算法，也不声称旧协议已有安全传输。
- 默认关闭 GM 监听；启用前必须具备身份、权限、审计和网络策略配置，缺少任何一项则拒绝启用。
  禁止默认管理员密码、硬编码万能票据、测试后门或前端保存服务密钥。
- 当前只读复核网页/API 保持只读，不复用其端点提供 GM 写操作。

## 2. 威胁与分层防护

| 威胁 | 网关侧能力 | 仍需其他层负责 |
|---|---|---|
| 连接洪泛、慢速连接、重连风暴 | 建连/握手超时、每连接与来源配额、重连退避、有限队列、过载拒绝 | 机房/云防火墙、上游清洗、负载均衡的连接保护 |
| 畸形包、超长载荷、解析资源耗尽 | 帧长/字段长度/嵌套深度/解析预算；启用压缩时限制解压后大小和比例；阶段/opcode 白名单 | 协议模糊测试、解析器修复，不能靠黑名单替代正确解析 |
| 撞库、暴力登录、账号枚举 | IP/账号/会话/动作组合限流、失败退避、必要时二次验证；外部错误避免泄漏账号存在性 | 账号服务安全存储密码、验证凭据、恢复账号流程 |
| 票据窃取/重放 | 用途与受众校验、过期/撤销、会话代数；协议支持时校验序号/重放窗口 | 端到端安全传输、设备与用户凭据保护；不能只加时间戳就声称防重放 |
| 封包修改、越权目标、非法调用顺序 | 类型/范围/协议状态校验、可信上下文构造、异常计数 | 业务层核对角色归属、战斗单位、回合、冷却、资源与服务端规则 |
| 重复消费、奖励复制、异常经济行为 | 限流、关联 operation_id、风险事件与告警 | 业务持久化幂等、账本、唯一约束、事务和对账；网关不能独自防复制资产 |
| GM 账号被盗、越权、内部误操作 | 独立身份、MFA、权限范围、敏感操作再认证、审批与操作审计 | 管理用例二次授权、业务校验、凭据轮换与人员权限回收 |
| 内部服务被冒用或权限滥用 | 服务身份、受众/消息类型限制、版本与大小校验 | 最小服务权限、秘密管理、业务端授权，内网不等于可信 |

**应用网关不能挡住超过链路带宽的 DDoS**。公网部署必须另行选上游网络防护与压测目标，
不作“网关能防所有攻击/外挂”的承诺。真实伤害、掉落、移动合法性等反作弊判定归服务端业务规则。

### 2.1 安全策略与风险事件

- 策略包括动作、范围（环境/区服/消息类型/主体）、阈值、持续时间、版本、原因和失效时间。
  配额数值由压测与风险评估确定，不在设计文档里虚构吞吐能力。
- 动作分级：观察/告警 → 限速/二次验证 → 暂时拒绝/断开；永久封号或大范围封禁走 GM 审批，
  不因一次异常包或单个弱信号自动永久封禁。
- 区分 IP 临时限制、账号封禁、角色禁言、会话撤销；共享 NAT 下不能简单“一人异常永久封整个 IP”。
- 请求携带的设备标识可伪造，只作辅助线索；第一版不加入侵入式设备扫描或客户端进程扫描。
- 真实来源 IP 仅从连接或受信任代理取得；只信任配置的代理来源传递的 PROXY/转发头，不能信任玩家自报头。
- 多网关阶段定义配额作用域与一致性方式，不能误把每节点限额当全局限额。
  风控依赖失联时维持有界本地限制，不无限放行；无法确认身份/撤销状态或 GM 权限的请求拒绝执行。
- 策略发布必须版本化、审核、灰度、可回滚；节点回报实际应用版本。
  未应用的新封禁不能显示全区服生效；强制撤销同步失效会话，并在业务接受边界拦截后续命令。
- 风险事件携带原因码、证据引用、策略版本与 trace_id；不记录密码、票据或无界原始封包。
  风险告警不是业务操作成功回执，也不是自动处罚的唯一依据。

## 3. GM 功能目录与业务归属

以下是设计范围，不是已实现接口。高风险写操作须等对应业务端口、事务和恢复语义就绪后开放。

| 能力 | GM 可以做什么 | 执行归属与约束 |
|---|---|---|
| 状态与查询 | 节点/连接/会话/队列/限流统计、在线人数、玩家状态和工单查询 | 网关只提供自身运行数据；角色/资产从业务查询端口读取，字段脱敏、分页、按区服授权 |
| 会话管理 | 踢下线、撤销会话、查看接管状态 | account/runtime 推进代数，旧消息不能继续写；不删除角色/战斗 |
| 账号处罚 | 限时封禁/解封、禁言/解除、原因与到期管理 | administration 协调 account/social；需申诉追踪，封禁、踢线、禁言不是同一操作 |
| 公告与维护 | 预览/发布公告、安排维护、停止新登录、限时排空、功能开关 | 对应运营/运行时用例；支持取消尚未生效的计划，不提供任意 HTML 或脚本注入 |
| 安全策略 | 查看告警、限流策略、临时访问限制、审批发布/回滚 | 安全策略控制端口负责版本、有效期、节点应用确认和审计 |
| 补偿与奖励 | 创建补偿计划、预览对象/总额、审批、执行及查询结果 | 既有 compensate 方向；approved_reward_plan_id 绑定不可变计划，资产/邮件/奖励事务内幂等执行 |
| 角色救援 | 有限制的卡点脱离/返回安全点、数据异常工单 | world/character 校验战斗、交易等状态；不强行改坐标或在线对象，未定义业务规则前不开放 |
| 配置与活动 | 查看版本、预览差异、审批激活/回滚已验证配置或活动计划 | 配置/活动拥有者执行；不提供任意文件上传执行，既有战斗固定规则版本 |
| 审批与审计 | 审批待办、工单关联、操作进度、审计查询/受控导出 | 独立权限；申请人不能审批自己的高风险请求，导出须脱敏与限量 |

禁止通用 SQL 控制台、远程 shell、eval/任意 Python、任意 module+method 调用、直接写玩家余额、
私有表或在线内存。紧急修复也必须走受控修复流程，不能借“GM 多功能”绕过业务一致性。
充值补单必须调用支付验证/对账用例，不以 GM 输入“已支付”替代渠道凭证。

## 4. 管理员身份、权限与审批

### 4.1 管理员不是游戏账号

采用独立 staff_principal_id、管理员会话与 authz_revision；玩家 RequestContext.account_id 不充当员工身份。
管理员票据有独立受众、用途与有效期，不能用于游戏登录；游戏票据也不能访问 GM。
生产管理员启用 MFA；高风险操作要求近期再认证。明确闲置超时、绝对有效期、退出与撤权即时失效。
浏览器控制台默认使用安全 HttpOnly/Secure 会话 cookie，明确 SameSite、CSRF token/Origin 校验与严格来源策略；
服务到服务凭据另行管理，不能借允许 CORS 替代鉴权或防 CSRF。

### 4.2 角色权限 + 资源范围 + 操作风险

| 角色建议 | 典型权限 | 默认禁止 |
|---|---|---|
| 只读客服 | 指定区服的脱敏查询、工单/操作结果查询 | 改资产、封禁、发布配置、导出全部用户 |
| 客服执行员 | 在授权范围内踢线、限时禁言/处罚申请 | 高额补偿、自我审批、跨区服操作 |
| 运营人员 | 公告/维护/活动/补偿计划申请 | 授权自己、绕过审批直接发奖 |
| 安全人员 | 风险审查、安全策略申请、会话撤销 | 随意改玩家经济数据 |
| 审批人员 | 明确类型/额度/范围的审批 | 审批自己申请的高风险操作 |
| 审计人员 | 授权范围内审计查询、受控导出 | 执行业务写操作、删除或修改审计 |

以上为默认角色建议，落实为 `permission + environment + realm_scope + target_scope + limits` 的授权矩阵。
角色名称和前端按钮隐藏都不是授权依据；目标逐一授权，不能以“能用批量接口”绕过对象范围。
管理员权限变更本身属于高风险管理操作，不能自己授予权限或生成不受限的审批身份。

高风险包括资产发放、批量/永久处罚、跨区服操作、全服开关/维护、安全策略放宽、权限授予。
要求独立审批、原因/工单、到期时间及限额；审批绑定不可变计划版本/摘要、对象集合、参数和配置版本。
任何范围/参数变化令审批失效。执行前及长任务分批执行时复核操作者/审批人权限与审批有效性；
撤权、过期、目标变化时暂停/拒绝未执行部分，不把一张旧审批单视为永久授权。

本地开发使用独立、显式启用的测试身份与测试区服，不与生产密钥/数据共用；
若允许单人测试审批流程，该例外仅可在不可访问生产的测试环境启用并保留审计。
应急访问是单独的短时最小授权 break-glass 流程，强认证、告警、审计和事后复核，
不是绕过鉴权/审计的万能密码。审计无法可靠落地时不开放高风险写操作。

## 5. 管理命令、可靠执行与审计

### 5.1 不复用万能字符串命令

现有 AdministrationAPI 只有 compensate / ban_account 类型声明，没有运行实现或完整管理鉴权。
现有 RequestContext 的 source=admin **不足以表达安全管理操作**，禁止现在就据此开放 GM API。

待联合冻结的契约：

- `AdminIdentity`：staff_principal_id、管理员会话、认证强度/再认证时间、authz_revision。
- `AdminActionContext`：request_id、稳定 operation_id、环境/区服、工单/原因、授权决定引用、审批引用、trace_id。
- 各操作的独立 typed DTO：处罚、撤销、公告、补偿、维护、策略发布等；类型白名单，不允许自由 method_name。
- `AdminOperationView`：requested/awaiting_approval/running/succeeded/partially_succeeded/failed/cancelled/unknown，
  以及目标级结果、业务回执和审计引用。仅持久化后的任务接受可返回 accepted，不能显示为业务完成。

这些名字是待实现设计端口/载荷，不是已经声明的新 Python Protocol。
集成负责人须与管理/账号/业务模块一起决定如何版本化扩展现有签名，不能把员工 ID 塞进游戏账号字段。

### 5.2 执行链路

1. 私有管理入口做认证、CSRF/重放防护、长度/频率控制及粗粒度权限检查。
2. administration 再次检查实时权限、环境/对象范围、审批、限额和业务前置条件。
3. 持久化管理操作记录及已授权的不可变执行计划后才接受任务；同 operation_id 不重复接受不同参数。
4. 调用白名单业务端口；操作身份沿调用链可验证地传递，不能仅用万能服务账号丢失真实操作者。
5. 业务提交、幂等结果和业务审计/outbox 同事务；不存在一个横跨网关/所有服务的假定大事务。
6. 返回回执并查询操作状态；异步执行采用有界工作队列、目标级去重、租约/fencing 或等效单执行者机制。
   网关超时/重启不自动重发补偿；结果未知使用同 operation_id 查询和恢复。

批量操作先预览并冻结对象集，执行逐项授权和计数；预览不预留资源也不保证执行必成。
部分成功不得显示全部成功，重试仅处理可安全恢复的未完成目标；取消只阻止尚未执行的部分。
回滚已经发出的资产属于新的、有审批与账本的补偿操作，不直接删流水或反向改数值。

### 5.3 审计要求

记录操作者/服务身份、认证与权限版本、环境/区服、动作与对象、原因/工单、审批人与计划摘要、
operation_id/trace_id、发生/接收时间、结果/错误码、业务回执与必要的脱敏前后差异。
拒绝访问、权限变更、批量查询/导出、审批、执行和紧急访问都在审计范围内。

审计采用追加写、最小权限、独立访问控制和保留/归档策略；GM 普通角色不能修改或删除。
部署时配置外部持久存储/防篡改归档与告警，不能仅因日志是 JSON 就声称不可篡改。
管理操作的关键审计/意图不能持久化时拒绝接受写请求；已经提交的业务不因外部审计投递故障回滚，
由同事务 outbox 重试并告警。高容量游戏拒绝日志可以聚合/采样，关键 GM 审计不可随意采样丢弃。
秘密与无关个人数据不落日志；审计查询同样按范围授权，保留期限和删除合规策略上线前明确。

## 6. 分期与目录所有权

| 阶段 | 交付范围 | 开放条件 |
|---|---|---|
| 第一条登录闭环 | 帧/状态校验、有限队列、多维限流、会话安全、拒绝与风险日志；保留 GM 独立入口但默认关闭 | 模糊输入、洪泛/慢连接、重放与旧会话隔离测试；没有保护完整的 GM 不开放 |
| 最小安全 GM | 独立身份/MFA/权限、审计、操作状态、脱敏查询、踢线/会话撤销、限时处罚 | 真实权限/撤权/持久化测试；处罚须等 account/social 对应规则完成 |
| 运营管理扩展 | 公告/维护、审批、补偿、安全策略发布、角色救援、配置/活动 | 每个业务端口具备事务、幂等和恢复测试；未就绪功能禁用，不用假数据冒充成功 |
| 多网关/生产强化 | 统一配额/策略版本、私有管理独立部署、外部防护、服务身份、密钥轮换与灾难恢复 | 多节点故障、上游防护、审批/审计恢复及容量演练 |

建议路径（新增目录仅为规划，本次不创建实现）：

| 路径 | 负责人 | 边界 |
|---|---|---|
| `transport/`、`protocol/` | 接入负责人 | 帧/连接安全、玩家白名单、可信来源解析 |
| `runtime/security/`、`runtime/` | 基础设施/安全负责人 | 执行已批准的策略、配额、风险事件和会话撤销；不发奖励或修改业务表 |
| `apps/gm_api/`、`apps/gm_web/` | 管理入口/界面负责人 | 私有 API 适配与控制台，前端没有权威权限或服务密钥 |
| `modules/administration/` | 管理业务负责人 | 授权协调、审批、任务/审计、业务操作，禁止通用 SQL/脚本接口 |
| `modules/account/`、各业务模块 | 对应负责人 | 实际处罚/撤销/资源/场景规则与持久化 |
| `contracts/`、`persistence/`、`migrations/` | 集成/数据库负责人 | 管理上下文、可靠任务/审计、幂等与数据库权限 |
| `deploy/`、`observability/` | 运维/安全负责人 | 网络分区、身份/密钥、告警、审计存储、外部防护 |
| `tests/protocol/`、`tests/modules/administration/`、`tests/integration/` | 对应组 + 独立验收 | 不改产品白名单去迁就测试替身 |

这些是职责组，不要求一个人承担全部工作，也不改变既有玩法目录所有权。

## 7. 必须新增的验收（本轮尚未执行）

- 玩家入口不注册 GM 路由；玩家票据、伪造 source/admin 身份、非可信代理头均不能越权。
- 不同管理员权限/区服/对象/额度隔离；直接请求隐藏按钮对应 API 仍被拒绝；敏感查询脱敏。
- MFA/会话过期、CSRF、撤权、票据重放与错误受众；内部服务身份或消息类型不符即拒绝。
- 自我审批、过期审批、修改已批计划/对象集、权限撤销后的待执行任务均拒绝。
- 畸形/超大/压缩炸弹载荷、慢连接、重连风暴、跨网关配额；资源保持有界并留下原因。
- 共享 IP 的正常玩家不因弱信号自动永久受罚；临时限制到期和审批解封有效。
- 重复补偿、同键不同参数、回包丢失/未知提交、工作进程重启，不重复发放；批量部分成功可正确恢复。
- 审计不可写时拒绝新高风险操作；外部投递故障保留 outbox；日志没有密码/票据，普通 GM 无权删改审计。
- 封禁/撤销作用于旧连接和排队命令；策略节点未确认应用不能虚报全服完成。
- 公告特殊文本不执行；禁止 SQL/shell/eval/任意代码入口；维护/救援不破坏已接受战斗或资产事务。
- GM 与游戏资源预算隔离；同进程故障局限记录清楚；私有管理入口与公网路由实际隔离，不能只检查配置文本。

本轮仅设计，不新增生产权限、不启用管理监听、不签发真实管理员身份，也不改客户端、复核批次或 game_data。
