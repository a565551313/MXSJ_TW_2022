# 各组第一轮交付

接口草案已建立，各组可以同时研究材料、补规则测试和定义私有模型；不是要求同一个人完成全部模块。

| 组 | 先做 | 首轮不得自行确定的跨组事项 |
|---|---|---|
| A 基础设施/认证 | 配置、启动/关闭、队列生命周期、TCP拆包、认证与会话接管、数据库工作单元方案 | 公共契约、依赖版本、迁移策略需集成负责人确认 |
| B 角色成长 | 角色属性/技能/外观材料清单、规则缺口、角色与技能只读快照草案 | 与E/F确认参战快照；与C确认学习/成长消耗 |
| C 资产与制造 | 物品/钱包模型、唯一约束、幂等与流水、配方规则 | 优先与I/G/E冻结事务内资产端口 |
| D 世界与交互 | 地图/NPC协议样本、坐标与移动规则、对话token、家园边界 | 世界→战斗交接与公共实体ID映射 |
| E 战斗 | 指令/战报表、纯回合计算骨架、确定性测试、恢复方案 | 属性/技能快照、消耗预留、奖励与世界归还 |
| F 宠物与子女 | 两套实例和培养模型、出战规则、可确认/待推断字段 | 参战单位快照、培养资源消耗 |
| G 任务与活动 | 任务状态机、活动/副本分类、服务端资格和奖励计划 | 不复制战斗与资产实现；资格与发奖同事务 |
| H 社交组织 | 队伍/帮派/关系状态和权限、频道限流 | 队伍成员快照、帮派资产不能直接改钱包 |
| I 邮件与交易 | 邮件/订单/托管/领取模型，重复操作和并发购买测试 | 必须与C共用同一事务，不能多个API分别提交 |

## 每组交付统一格式

1. 客户端条目ID、路径、函数与协议证据。
2. 可直接提取的数据、可移植规则、需要新实现规则，三者分开。
3. 对外接口及校验/错误表；新增接口提交给调用方评审。
4. 本模块私有数据模型、索引与迁移需求。
5. 使用 fake 依赖的规则测试；之后增加真实集成测试。
6. 已完成/部分完成/待验证清单，不用“全量成功”掩盖反编译或语义缺口。

## 集成门槛

骨架检查 → 模块契约评审 → 核心事务端口冻结 → 模块规则测试 → 跨模块数据库测试 → 原客户端协议联调。
目录与公共起步接口现在已经落地；未冻结的高级接口允许研究并行，但不得各自发明冲突的数据所有权。
