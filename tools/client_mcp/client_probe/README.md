# client_probe — 客户端内探针占位

> 状态：已实现独立只读采集内核；尚未选择 FLS 挂点、接 IPC 或在定制游戏 VM 内加载。  
> 本目录存放运行在客户端老 Python VM 内的自写探针，以及后续生成测试包的构建入口。

## 未来文件候选

```text
mxsj_probe.py              # 客户端内 Python 2.5 探针
harness.py2                # 离线桩测试，不执行原游戏模块
build_probe_package.py     # 基于用户修改版 script.fls 生成测试包
probe_report.schema.json   # 探针报告 schema
```

## 关键约束

1. 探针必须适配客户端实际 VM；当前主游戏脚本 VM 是定制 Python 2.5，不能使用 Python 3 语法。
2. 不执行反编译 / 恢复出来的游戏模块。
3. 不覆盖用户输入包或仓库原始包。
4. 探针挂点必须等用户修改版 `script.fls` 到位后只读核对再定。
5. 第一阶段只读，不提供任意命令执行。
6. 所有客户端内部调用必须考虑主循环 / 线程安全。
7. 报告必须脱敏，不记录账号密码。

## 当前状态

- `mxsj_probe.py` 可在 CPython 2.5.6 中内存编译并调用，不写 pyc。
- 当前只采集 Python 版本、注入的非负数运行时计数、固定标准模块加载状态；原生 API 返回 `unknown`。
- 不读取游戏对象、不执行恢复代码、不自行导入未知模块、不包含 IPC 或自动挂点。
- 本地 `data/script.fls` 已登记并与 Git 基线完成只读目录/载荷比较；仅四条存储载荷变化，语义和挂点仍需对当前载荷单独解码核验。

后续接入必须基于当前载荷确认模块身份和安全执行时机，再生成仓库外测试副本。
