## 2. 两条通道必须分开

### 2.1 游戏业务通道

```text
mx.exe <-> 隔离测试服 / mock_server_v2
```

这条通道仍走游戏原生 TCP 协议。MCP 不替代游戏协议，也不把 MCP 地址填进游戏服务器配置。

### 2.2 测试控制通道

```text
MCP Client <-> MCP Server <-> 客户端内探针
```

这条通道用于开发工具读取客户端状态、运行受控测试场景、收集报告。默认只在本机或受控私网内使用。

## 3. 部署模式

### 3.1 Windows 本机模式

MCP Server、客户端探针、游戏测试副本都在同一台 Windows 机器上。

- 编程工具可用 stdio 启动 MCP Server。
- 也可用 Streamable HTTP 连接本机 `127.0.0.1`。
- IPC 优先本机命名管道；若使用回环 TCP，必须限制本机并鉴权。

### 3.2 Linux 开发模式

Linux 沙箱没有真实 Windows 游戏客户端，只能运行：

```text
MCP Server <-> fake probe
```

用于验证协议、传输、工具定义、会话锁、报告格式。fake probe 通过不能写成真实客户端通过。

### 3.3 远程验收模式

如果未来需要 Arena 沙箱或其他远程开发环境直连 Windows 客户端，需要额外安全网关：

```text
远程 MCP Client -> HTTPS + token -> Windows MCP Server -> 探针
```

该模式不是第一版默认能力。必须默认只读、强鉴权、审计、限制来源，不暴露游戏端口。

## 4. 客户端内探针原则

1. 探针必须是自写代码，不执行反编译恢复稿。
2. 探针运行在客户端实际脚本 VM 内；本客户端主游戏脚本 VM 为定制 Python 2.5，不能用现代 Python 3 语法。
3. 第一阶段只读：VM 信息、模块状态、原生模块可用性、日志、后续界面/角色/地图状态。
4. 不在 IPC 线程直接调用客户端对象；所有客户端内部访问必须排到客户端主循环或已验证的安全执行点。
5. 不记录账号、密码、票据、密钥、完整聊天隐私。
6. 探针失败不能静默吞掉；必须输出可诊断错误，但不得泄露敏感值。

## 5. script.fls 输入基线

`data/script.fls` **在仓库内就地修改**（用户 2026-11-03 授权并自行备份）。不再有仓库外输入目录与修复包：

```text
用户修改版 script.fls
  -> 记录修改前 SHA-256 / 大小
  -> 就地修改并逐条校验
  -> 只读解析条目清单
  -> 与原始基线差异报告
  -> 确认探针挂点
  -> 生成新的测试副本 script.fls
```

工具、报告与运行期文件都留在仓库内：

```text
tools/client_mcp/
├─ runtime/     # 令牌、端口、MCP 配置、临时包（gitignore）
├─ dist/        # 可选构建产物（gitignore）
└─ reports/     # 本地报告（gitignore）
```

## 6. 第一阶段数据流

```text
1. Windows 客户端测试副本启动
2. 客户端脚本加载探针模块
3. 探针采集只读运行时信息
4. 探针写报告文件，或后续通过本机 IPC 发送 hello / report
5. MCP Server 读取报告快照或校验 IPC 会话
6. MCP Client 调用 client_get_probe_report
7. MCP Server 返回脱敏后的 JSON 报告
```

## 7. 后续受控操作

只读闭环稳定后，才允许增加：

- 读取指定 UI 状态；
- 触发已验证界面消息；
- 调用已验证原生函数；
- 运行登录 / 选角 / 进图 / NPC / 传送场景。

每个操作都必须有：

- 白名单名称；
- 参数 schema；
- 前置状态；
- 主循环调度；
- 超时；
- 操作前后状态；
- 错误码；
- 审计记录；
- 会话独占锁。
