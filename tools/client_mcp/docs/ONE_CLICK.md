# 一键启动：用户流程

> 2026-11-03 用户明确要求：涉及开发、测试、工具配合的环节**一律不许让用户使用命令行**；所有改动都在仓库内完成；工具要像 UI 编辑器 / 脚本编辑器 / 资源编辑器那样**双击即用**，自己检查环境、自己补依赖。

## 1. 用户需要做的事

只有一件：

```text
双击 tools/client_mcp/启动客户端MCP.bat
```

想确认仓库里的客户端包是哪一个，**双击** `检查当前客户端包.bat`，窗口用一句中文给出结论
（无钩子版 / 受保护钩子版 / 坏包 / 原始基线 / 不认识的包），不需要用户比哈希。

游戏由用户自己启动。工具不代启动游戏，也不会在用户没有双击时后台常驻。

## 2. 启动器自动完成的事

| 步骤 | 行为 | 失败时 |
|---|---|---|
| 1 | 找 Python（优先 `py -3`，其次 `python`） | 窗口给出 python.org 下载地址并停住 |
| 2 | 检查 Python ≥ 3.10 | 同上 |
| 3 | 检查 `mcp` / `uvicorn` / `starlette` | 自动 `pip install`，官方源失败换清华、阿里云镜像，装完复检 |
| 4 | 生成本机访问令牌 | 写入 `runtime/http_token.txt`，以后复用 |
| 5 | 选空闲端口 | 8765 起往后找 20 个端口 |
| 6 | 查找客户端报告 | `runtime/`、工具目录、仓库根、`data/`、`log/`、`inputs/*/` 里最新的 `mxsj_probe_report.txt` |
| 7 | 写编程工具配置 | `runtime/mcp_client_config.json`（含 URL 与 Bearer 头） |
| 8 | 启动 MCP 服务 | 窗口显示接入地址；关闭窗口即停止 |
| 9 | 监视报告变化 | 客户端在跑时打印一次“报告每秒更新”；关掉后打印“已有 N 秒没更新”（阈值 15 秒，避免读图误判） |

## 3. 用户需要回传的东西

出问题时**只需要**：

1. 启动窗口里的文字（截图或复制）；
2. `tools/client_mcp/启动日志.txt`。

不需要用户执行任何诊断命令。

## 4. 明确禁止的交互方式

以下要求一律不许出现在面向用户的流程或文档里：

- 让用户 `cd` 到某个目录、运行 `python xxx.py`、`pip install`、`set` 环境变量；
- 让用户自己生成 / 复制令牌、查端口、改防火墙；
- 让用户手写 MCP JSON 配置（应自动生成，用户只需导入）；
- 让用户解压到“正确的独立目录”、覆盖文件、去仓库外找产物；
- 让用户用命令行“验证服务是否启动”。

开发者自检命令（`--check-only`、pytest、ruff）可以保留在开发者文档里，但必须标注“普通使用不需要”。

## 5. 产物位置

- 运行期文件：`tools/client_mcp/runtime/`（已 gitignore）。
- 日志：`tools/client_mcp/启动日志.txt`（已 gitignore）。
- 修复包 / 测试包 / 报告：一律放在仓库内固定位置，不再放 Google Drive 或仓库外目录。

## 6. 当前状态

- 本流程已实现：自检、自动装依赖、令牌、端口、配置生成、报告发现、状态打印。
- 尚未实现：报告与运行中客户端的**实时**直连。启动器当前启动的是报告快照桥；实时 IPC 完成后，启动器的交互方式不变。
