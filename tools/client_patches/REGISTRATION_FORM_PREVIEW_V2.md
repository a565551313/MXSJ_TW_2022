# 注册资料页离线预览 v2

2026-10-12。状态：**v1 + v2 共 26 项离线补丁检查通过，v2 Windows 原生实测待用户反馈**。
这是在 v1 用户验证之后的下一小步，不是可用的账号注册接口。

## 行为

| 操作 | v2 预期 |
|---|---|
| 首页「申請會員」 | 内置条款第一页 |
| 条款页「我同意」 | 进入原 CRegPanel2 / `login/reg2.dlg` |
| 条款页「我拒绝」 | 返回首页 |
| 资料页输入 | 可检查旧字段/遮罩/焦点/长度；仅使用假数据 |
| 资料页下一步 | 本地提示「離線預覽，未送出。」；不校验/提交/模拟成功 |
| 原 2980 邮箱链接 | 改为「離線預覽說明」，只显示相同本地提示 |
| 资料页返回 | Step(0) 返回条款页；Save 为 no-op，不保存字段至 g_AccountInfo |
| 验证码/HTTP/外部注册网站 | 保持阻断，不进入 2980 注册流程 |

`CRegPanel2.__init__` / `CreateEdits` 无直接注册 HTTP/浏览器调用；已有验证码编辑框及刷新链接初始隐藏，
原来的显示条件/输入控件/资源路径不改变。本轮不验证这些资源实际加载成功，必须在用户完整安装上确认。
页面初始化本身没有直接调用注册请求，不等于整个客户端不会联网：原新闻、资源加载、官网等仍独立存在。

## 实现边界

从**原始已锁定哈希**生成 v2，不在 v1 上叠加字节修改。新增 `--stage form`，缺省 `--stage terms` 仍可
重建与已交付 v1 完全相同的 FLS（新增回归断言）。原包和密钥库不变。

entry 337 复用 v1 的局部注册入口修改。
entry 4007：

1. CRegPanel1.OnMessage 保留 Step(1)，随后跳过旧点击统计；拒绝仍复用 v1 的安全返回路径。
2. CRegPanel2.DoNext 整体替换为明确的本地提示调用，不读取字段、不调用 Save/DoCheck/设备信息/MD5/注册 HTTP。
   这并不是声称表单校验已通过，空输入同样只显示离线提示。
3. CRegPanel2.Save 与 Register2980 早退；资料页旧邮件链接转向本地提示，不触发旧统计。
4. 其余 8 个注册模块直接 HTTP/浏览器调用函数保持早退。
5. 只修改两个已有的 CP950 字节串：提示语及旧邮件链接标签。按原长度填充，不改 marshal 布局、常量数量、
   路径、XOR 边界。原始串、编码、唯一性、范围与所有非目标常量都参与检查。

函数字节码仍为定长替换；未重新编译历史反编译源文件，没有运行任何恢复脚本。
现有输入框逻辑仍会读取字段用于本地显示/焦点行为；禁用 Save 不等于可以安全使用真实密码。
不改原服务条款、品牌或底图，不主张它们适用于将来的自建服务。
