## 行为与暂定规则

- 下一步：必填 → 密码长度 → 两次密码一致 → 邮箱长度 → 基础邮箱格式。
  首个失败项显示错误，留在表单；全部通过也只显示「離線預覽，未送出。」。
- 离线预览说明：无条件显示上述离线提示，不调用校验、不读取任何输入框。
- 上一步：回条款，不校验、不保存输入；拒绝回首页继续沿用已验收路径。
- 邮箱首尾空白去除后校验；密码只用 strip 判断是否全空白，不修改密码本身或确认值。
- 必填项：密码、确认密码、主邮箱；空串或全空白均拒绝。
- 密码长度：6–16；确认值与原密码大小写敏感、逐字节比较。
- 邮箱长度：最多 32，沿用当前编辑控件限制；小于 5 不能通过基础格式检查。
- 邮箱格式：ASCII 基础 local@domain.tld 结构，域名段不含下划线、空白或空段。
  支持常见大小写、域名连字符和多级域名；不做 MX/DNS 查询或邮箱所有权验证。
  这是较宽松的基础语法筛查，不是完整 RFC 邮箱解析器（例如不能据它保证局部点号或域标签边界均符合 RFC/DNS）。
  现有 CMailEdit 字符输入过滤保持不变，不新增对国际化地址、引号地址或 plus alias 的支持。

32 字符不是邮箱通用标准上限；6–16 也不是最终服务端密码策略。本轮刻意与旧输入控件限制对齐。
控件自身 SetLimit 也会限制输入；提交检查仍有上界防御，测试器直接构造超长值覆盖该分支。
后续须按新账号服务规范统一调整客户端和服务端，服务端必须重复校验，不能信任客户端的通过标志。
不向日志、全局 g_AccountInfo、文件或网络写入输入字段。这里不是全客户端日志/网络隔离承诺。

## 有界实现

从锁定原包新增 `--stage form-validate`；旧 terms/form/form-basic 的二进制哈希保持可重现。
沿用 v2.1 对 email2、验证码和旧注册网络流程的禁用，不引入它们作为校验条件。

新编写的四段 Python 2.5 指令固定宽度覆盖旧函数体，标签经解析生成对齐跳转：

- DoCheck：仅读三个基础输入框，返回错误文字或 None；不访问被省略的控件，不切换焦点/页面，不保存字段。
- CheckEmail：长度检查及 re.compile/match，使用恰好 37 字节的基础 ASCII 正则替换旧正则。
- DoNext：接收明确的校验开关；开关为真时先 DoCheck，否则直接本地提示。
- OnMessage：消息 1 → Step(0)，消息 2 → DoNext(1)，消息 3 → DoNext(0)，其余忽略。

DoNext 的 argcount 由 1 改为 2，复用旧第二局部变量槽 msg，不增加 nlocals 或 stacksize。
两个调用点一起更新并验证参数数量。仅此一处允许 argcount 元数据变化，其他元数据仍严格比较。
DoCheck 中旧验证码常量 4 改为 16、CheckEmail 旧上限 50 改为 32；按原 32 位宽度替换。
提示串固定 CP950 字节宽度补空格；不移动 marshal 布局、代码对象边界或 XOR 分段。
全新逻辑的 lnotab 仍为原始映射，不代表新逻辑的准确源码行号；若后续出错，结合函数名、补丁报告和日志分析。

仅替换归档 337/4007，其他 5000 条目录记录及压缩载荷不变。源 FLS、密钥库、master、生产数据不变。
