# 新版编辑器：新增与持续修改布局

版本：资源编辑器 **0.4.3** / UI编辑器 **0.8.3**。

这次修在两个编辑器本身，不是一次性修包工具，不限制注册两路径，不导入仓库模板。
新增/修改布局入包均采用原生路径密钥，保留当前用户布局与Big5文本/GBK路径规则。
散装 `.dlg` 仍保存明文，入包时自动编码。原包只读，始终输出新包。

## 现有注册布局继续调整

1. 用 UI 0.8.3 打开**你当前已调整的** interface.fls，不换回原版/仓库模板。
2. 打开 `login/regterms.dlg`，保留或继续修改当前布局，点“保存回资源包”，生成 A.fls。
   即使暂时不改字段，也可保存，将这条旧明文/错误密钥迁移为原生格式。
3. 保存成功后工具接续新包。确认当前来源是 A.fls，从中打开 `login/regform.dlg`，
   保留/调整当前布局，再保存生成 B.fls。最后测试的是 **B.fls**，不是 A 或旧包。
4. 后续从最新输出包继续开、改、保存；不用每次重新导模板，也不用另跑存储修复助手。

迁移只针对明确保存的目标布局，其它未修改布局保持原字节。若只保存一张，另一张
旧存储不会自动修；这样避免静默迁移/改写用户所有资源。

## 任意以后新增布局

- UI工具：在包根右键“导入布局到此包…”，选择自己的 `.dlg`，填写完整相对地址
  （如 `future/my_dialog.dlg`），确认后编辑、保存新包；重开最新输出包继续改。
- 自定义路径在本机应用设置中记忆；换机/删除设置后，可在包根“按包内路径打开布局…”
  输入精确地址恢复。0SLF没有文件名表，不承诺从编号反推出所有名字。
- 资源工具：正常“按路径导入/替换” `.dlg`，明文或可识别的旧密文都自动按目标编号
  原生编码，不双重加密。编辑导出文件后按**同一完整地址**替换，再输出新包。
- 入包不自动接脚本、不自动带所有引用图片；游戏真正使用新增布局仍需相应调用入口。
- 使用相对GBK可编码路径，拒绝绝对地址、`..`、NUL与不可编码字符；不靠替换字符猜路径。

## 安全与验证边界

写后验证用原生路径密钥解密目标，不再靠猜密文头的编辑器自洽校验。布局源码仅作
受限AST字面量解析，**不执行游戏布局/脚本/原DLL**。保存失败不替换原包或已有输出。
高级原始存储API不自动修改输入，但已识别改动布局也必须通过保存阶段原生校验。

本轮离线结果：资源118项通过；UI204项（1跳过、无失败）；注册23项（含真CPython2.5.6）通过。
UI跳过项为环境相关项，Qt使用Linux offscreen测试，不等同Windows/游戏实测。
独立原生公式探针复现旧版本两个新增失败，修后两个通过。
