# MXSJ UI 编辑器（ui_editor）

> **能力边界**：当前版本以 `src/ui_editor/__init__.py` 为准，实测与未验范围见 [STATUS](../docs/STATUS.md)。布局编辑不会自动修改对应脚本接线；固定三分九宫格近似不等于原生像素级一致。
> 仅生成新包并保护源资源；完整 `.dlg` 语料为外部材料。文本支持 UTF-8 读写不等于游戏支持该编码。共享核心按 [mx_common](../mx_common/README.md) 的真源／副本规则维护。

可视化编辑梦想世界客户端 UI 布局（`.dlg`）的独立工具：能打开
现有布局修改，也能从空白新建布局。布局格式、路径哈希、包内
解密均来自本仓库的逆向结案成果（见 `notes/fls_path_hash_and_dlg.md`）。

当前版本：**0.13.2**（新建拼名族：几张图直接变成一个按钮/边框，连图带命名写进包；
图片不用改名——按文件名认左中右/上下中，认不出按文件名排序；按 PR #71 的
AI 审查修掉属实项：Windows 新建族的 KeyError、竖排名/`①` 名的崩溃、
批量导出丢族名、`.igs` 族漏判覆盖）。

## 0.13.0：新建拼名族——几张图直接变成一个按钮

**用户需求**：手里有几张图（例如按钮的三态横片），想一次导入成一个按钮，
而不是一张张加进去再手打名字。

**用法**：属性面板 `sFileName` 那行点「…」→ 选图窗点 **「新建拼名族…」** →
多选图片 →「这一族的目录路径」填 `combdialog4\新登陆界面\三态按钮\登录按钮\`
→「族类型」自动选好（可改）→ 确定。

**先说清楚一件事**：游戏里的按钮不是"一张图"，是**左 + 中 + 右三片**拼出来的，
中间那片会被拉伸填满按钮宽度。所以：

| 选几张 | 变成 | 写进包的条目 |
|---|---|---|
| **3 张** | 按钮的 **1 个状态**（常态） | `0l.png 0c.png 0r.png` |
| 6 张 | 按钮的 2 个状态（常态 + 悬停/按下之一） | `0l 0c 0r 1l 1c 1r.png` |
| 9 张 | 按钮的 3 个状态 | `0l … 2r.png` |
| 9 张（九宫格控件） | 九宫格边框 | `top\left.png` … `bottom\right.png` |
| 3 张（横/竖边框控件） | 横三片 / 竖三片 | `left/middle/right`、`top/middle/bottom` |
| N 张 | 逐帧动画 | `0.png 1.png …` |

> 界面上的"按钮横片"就是上面这个族（旧称"三态横片"，容易被读成"必须三个态"，
> 已改叫"按钮横片"）；张数不是 3 的倍数时对话框会直接说明原因并不让确定。

**目录名就是按钮的"身份"**（最容易误会的一点）：

- 目录路径不是"某个要覆盖的按钮"，而是**你给这一族起的名字**。游戏里
  `…\登录按钮\` 这个目录下的 `0l/0c/0r` 就是「登录按钮」的图；
- 所以**写已有目录 = 替换那个按钮的图**。做**新**按钮就换一个新目录名
  （例如 `…\三态按钮\我的按钮\`），控件再指过去即可，原来的按钮一根头发都不动；
- 对话框会当场算清楚：目录里已有同名图时红字警告「继续并保存回包会替换它们」，
  逐条标「（替换）」，确定按钮变成 **「替换 3 张」**，并给出
  **「换个新目录（不覆盖）」** 一键改成 `…\登录按钮_2\`。

### 我的图片要叫什么名字？（0.13.1）

**不用改名，直接多选就行。** 程序按下面的顺序判断，对话框里会逐条写出
「哪张图 → 哪个条目」，选完先看一眼图，对不上再改名或重选：

1. **文件名就是族内命名**（最稳）：`0l.png / 0c.png / 0r.png`、`top-left.png` …
   ——原样对应，和选择顺序无关。刚导出的图改完再导回来就是这种。
2. **文件名是左中右 / 上下中**（中英都行）：认得出就按方位对，
   **和选择顺序无关**——你选成 右、左、中 也会配成 `0l←左 / 0c←中 / 0r←右`：

   | 方位 | 认得的写法（大小写、`-`/`_`/空格都行） |
   |---|---|
   | 左 | `左`、`left`、`l`、`0左`、`左-中`、`中左`…… |
   | 中 | `中`、`middle`、`center`、`c`、`m`、`中中` |
   | 右 | `右`、`right`、`r`、`0右` |
   | 上 / 下 | `上`、`top`、`t`、`上中`、`top-middle`、`左上` |
   | 九片缩写 | `tl tr ml mm mr bl bm br`、`top_left`、`T-L`、`上-左`（顺序反过来也认） |
   | 逐帧 | `frame0.png`、`第0帧.png` → `0.png` |

3. **认不出方位**（`1.png`、`2.png`、`10.png`、截图名字）：**按文件名自然排序**
   依次对应（`1` 在 `2` 前面、`2` 在 `10` 前面，不按"你点的先后"），
   界面会写明「已按文件名排序依次对应」。

**控件类型优先**：你在按钮上点「新建拼名族…」，文件就算叫
`left/middle/right.png`，写进去也还是按钮要的 `0l/0c/0r`（写 `left.png` 游戏
找不到、按钮会画不出来）。这时对话框会多一行「文件名更像【横三片】，但控件是
【按钮横片】，按后者写入；要改就在上面切换类型」。唯一的例外是 9 张按
`top-left…` 命名的——那是明确的九宫格，按九宫格写。

**同一个按钮的多态**：`0l/0c/0r` 是第 1 个状态，`1l/1c/1r` 是第 2 个状态。
只导出**第 2 态的 3 张**（文件叫 `1l/1c/1r`）导进来也认作这个族的第一态——
单态族里状态号是多余的。也可以直接写 `0左/0中/0右`。

**想要更省事的命名**：一族图放进同一个目录、按
`0l 0c 0r`（多态 `1l 1c 1r` …）命名最省事——它同时是"名字即位置"和"导出再导回
不会错"的形式。

**写的是真素材**：

- 整组 `.igs` 原样写入（不重新编码），其余统一转 PNG（游戏只认 `.png`/`.igs`，
  jpg/bmp 原样写进去等于坏图）；`.igs` 与普通图片混选会直接拒绝——拼名族要求
  整组同扩展名；
- 张数不对（例如 4 张选「三态横片」）不让确定：拼名族是"整族齐装"才生效。

**保存回包**：布局引用的是**目录**，而挂账的是它下面的子图。旧筛选只认
"完整字符串被引用"，新建的族会被当成未被引用丢掉、存出一个空族；现在
`referenced_staged_images` 把被引用目录下的子图一起带上（`…\登录按钮2\` 这种
前缀相同的不会被误吃）。选图窗清单也只列族本身，不把 9 张子图平铺出来。

**验证**：真 0SLF 包走完整窗口链路——3 张图 → 新建族到**新目录** `…\我的按钮\`
→ `sFileName` 跟着指过去 → 保存回包 `images_added=3`、`images_replaced=0`、
`staged_unreferenced=[]`、回读布局仍是目录路径、三个子图字节与本地文件逐字节
一致、全新解析器能拼出这张按钮，**原「登录按钮」的 3 张图字节未变**；
指向**已有**目录时保存则是 `images_replaced=3`（原按钮被替换），对话框事前已
红字警告。九片 9 张（乱序选择）折叠成外层目录而不是三个行目录；6 张自动成
2 态；认不出文件名时按文件名自然排序分配（0.13.1 起；此前是按选择顺序，
用户指出不可预期）。`ui_editor` 全套 **679 项**（命名识别 11 + 审查修复 6）：676
无失败（含 1 跳过）、2 项基线 `QMenu already deleted`。

边界：沙箱 offscreen + 合成夹具；没在真实 `interface.fls` 上验证；导出的是
子图原字节，与游戏内最终效果无关。

## 0.12.9：从资源包选择能选「拼名族」了（按钮、边框、九宫格）

**用户的卡点**：`sFileName` 要填 `combdialog4\新登陆界面\三态按钮\登录按钮\`
这种目录型基路径，但「从资源包选择」里只有单张图片，翻不到目录，只能手打。

**为什么会这样**（三层都把它滤掉）：

| 层 | 旧行为 |
|---|---|
| `_scan_media_in_text` / `_looks_media` | 只认**带扩展名**的引号字符串，`…\登录按钮\` 没有扩展名 → 根本不进候选 |
| `media_candidates` | 用 `_exists()` 判「包里有」，而目录条目在包里**不存在**（运行时才拼）→ 一律丢掉 |
| 属性面板 | 只留 `endswith(".png"/".igs"…)` 的路径 → 目录路径再次出局 |

**改法**：

- `_looks_media` 认目录型基路径（结尾分隔符）；
- `media_candidates` 改用 `_media_available()`：普通资源仍看条目在不在，目录型
  基路径改用与画布同一个 `dir_base.plan` 判「**整族齐装**」——拼不齐的族不进
  清单（避免选了画不出来）；
- `dir_base.describe()` 给出一句话说明（`三态横片 · 2 态` / `九片 · 9 块`），
  选图窗标签显示成 **`登录按钮（三态横片 · 2 态）`**，悬停看完整路径；缩略图用
  `fetch_image` 拼出的族预览；新增 **「只看拼名族」** 勾选框，单族批次不显示；
- 属性面板的图片字段放行目录型基路径（音效字段不放行），选中即把
  `…\登录按钮\` 写回 `sFileName`；
- 选图窗的「导出图片…」对族也生效：按族内每块导出（`0l.png`…`1r.png`、
  `top-left.png`…），不再当成一个文件去另存为。

**两种用法**：资源包里已有这族 → 选图窗勾「只看拼名族」或直接搜「登录按钮」；
族是新的、包里还没有 → 先按名字把图加进包（见下节「添加新图到包」），或直接
在 `sFileName` 里手打路径（0.12.5 之后画布本来就能按族绘制）。

**验证**：真 0SLF 包（布局引用 `test/btn\` + 六张真 PNG 子图）走完整窗口链路：
候选只出 `btn（三态横片 · 2 态）`，选中回写 `test/btn\`，画布重绘正常；
729 个族在散装目录上的可用性核对 **0.56 s**（首次整理清单时一次性，结果缓存）。
`ui_editor` 全套 **640 项**：637 无失败（含 1 跳过）、2 项基线 `QMenu already deleted`。

## 0.12.8：目录型基路径的素材终于导得出来（按钮、边框、九宫格）

**用户实测报的错**（画布右键「导出素材」，`sFileName` 是
`combdialog4\新登陆界面\三态按钮\登录按钮\`）：

```
导出被拒绝（1 个）：combdialog4\新登陆界面\三态按钮\登录按钮\ —— 资源路径不能以目录分隔符结尾：…
没有可导出的素材（包内找不到：combdialog4\新登陆界面\三态按钮\登录按钮\）
```

**根因**：结尾带 `\`/`/` 的是**目录型基路径**——包里根本没有这个条目，客户端
运行时才拼出 `0l.png`/`0c.png`/`0r.png`、`top/left.png` 这些子图。导出链路却把它
当成一个普通资源路径去 `fetch_bytes`：

| 分支 | 旧行为 |
|---|---|
| 按原格式 | `fetch_bytes` 抛 `资源路径不能以目录分隔符结尾` → 被 `except ValueError: return []` 吞掉 → 外层当成「包内找不到」 |
| 转成图片 | `fetch_bytes` 的异常原样进 `rejected` → 状态栏把路径校验器的原话甩给用户 |

整条导出链路**从未调用** `dir_base.plan`（只有画布、诊断、切片在用），所以族里
那些真实存在的子图一张都不会被导出。真包实测 729 个目录型基路径（切片类 297 个）
都受影响。

**改法**：

- 新增 `core/asset_export.py::dir_base_pieces / export_paths / dir_piece_stem /
  dir_piece_name / unexported_label`：目录型基路径按画布同一个
  `dir_base.plan` 展开成族内**每块子图**；按原格式与转成图片两条分支共用；
- **文件名保留族内相对路径**：三态横片 `0l.png`…`1r.png`，九片
  `top-left.png`…`bottom-right.png`。只取 basename 会让九片的 `top/left` 与
  `bottom/left` 挤成 `left.png`/`left-2.png`，看不出是哪一块；
- 跨控件去重按**子图**（不是基路径）记账：两个控件引用同一个按钮族只导一份；
- 提示口径分开：拼不出整族时说「目录型基路径：包里拼不出整族子图」，不再出现
  「资源路径不能以目录分隔符结尾」「包内找不到」这种误导；真有文件缺失仍逐块点名。

**PR #70 复核补修**（AI 审查两条，核实后都属实）：

- **一批导多个按钮族时文件名分不清**：`登录按钮\` 与 `注册按钮\` 都产出
  `0l.png`，后一族被改成 `0l-2.png`。现在同一批出现多个基路径时按**最短可区分
  尾段**加前缀——`登录按钮-0l.png` / `注册按钮-0l.png`；两族末级同名时自动退到
  上一级（`三态按钮-登录按钮-0l.png`）。单族批次不加前缀，文件名不变。
- **残族被当成完整导出**：族里某块在索引里有、取字节却失败（`None` 或被拒）时，
  旧代码只跳过它，`missing` 为空。现在逐块记进状态栏
  （`…\0c.png（子图读取失败）`），不再把缺块的残族说成「已导出」。

**验证**：`ui_editor` 全套 **636 项**（新增 16：纯逻辑 9 + GUI 7）：633 无失败
（含 1 跳过）、2 项 `QMenu already deleted` 为基线既有；`ruff check` 0、
`check_windows_compat` 0/0/0。
真 `AssetResolver`（散装目录）走完整窗口链路实测：三态按钮导出 **6 个文件**
（`0l/0c/0r/1l/1c/1r.png`，字节与来源逐字节一致）、九片 **9 个文件**
（`top-left.png` …）、缺块时状态栏给族原因；一批导两个按钮族时两条分支都得到
`登录按钮-*.png` / `注册按钮-*.png` 共 12 个文件。边界：仍是沙箱 offscreen + 合成夹具，
未在真实客户端包上跑；导出的是子图**原字节**，与游戏内最终拼出来的效果无关。

## 0.12.6：批量导出素材不再覆盖、不再重复、不再一次失败全丢

**原来为什么不生效**：`export_widget_assets` 是「多选导出一批」的入口，但它是照着
「一次导一个素材」写出来的，三个坑叠在一起：

| 现象 | 原因 |
|---|---|
| `a\btn.png` 与 `b\btn.png` 导出后只剩一个，内容还是后写的那张 | 「转成图片导出」用的 `image_export.export_image_files` 只取 `_basename` 拼目标名，**从不查重**；`guard_output` 只拦源资源别名和符号链接，**不管同名普通文件**。批量里后写的把先写的盖掉，`written` 还把两者都记成成功 |
| 多选几个控件共用同一张背景图，目录里冒出 `bg.png` + `bg-2.png` | 原格式分支按控件逐个调 `export_raw_assets`，没有跨控件的「这个素材已经导过」记忆（`unique_target` 只防覆盖、不防重复） |
| 某个目标被拒（例如导出目录里有同名符号链接），整批直接停，已经写出的文件也不提 | 整个循环包在同一个 `try` 里，`except ValueError` 只打一行状态就 `return`，`written` 丢了 |

改后的用户可见语义（**批量**导出，单张导出行为不变）：

- **同一个资源路径只导一次**（`img\bg.png` 与 `img/bg.png` 视为同一个）；`.spr`
  连带导出的帧图同样去重，两个 `.spr` 指向同一张图不会导两份；
- **同名不覆盖**：不同目录下的同名素材 → `btn.png` + `btn-2.png`，多帧精灵
  → `hero-0.png`、`hero-1.png`，第二份是 `hero-0-2.png`、`hero-1-2.png`；
- **拒绝不连累整批**：被 `guard_output` 拒绝的目标记一条，其余照常导出，状态栏
  同时报「已导出 N 个」和「M 个被拒绝：…」；一个都没写成时直接报拒绝原因，
  不再笼统说「没有可导出的素材」；
- 单张导出（属性面板的保存框）仍按原样覆盖同名文件——那是用户指定的目标名。

「从资源包选择」对话框里的**批量导出图片**走的是同一条 `export_image_files`，
同步修好了同名覆盖与一次失败整批中止（导出完成后对话框会列出被拒的文件）。

- **ui.lst 样式表皮肤**：`CTextButton` 等带 `iStyle` 的按钮，图片取不到时
  按样式表里的 `ButtonNormalColor` 画底色（改 `iStyle` 颜色就变）；
- **脚本现造皮肤**：脚本在锚点控件上现造按钮，画的是索引里的皮肤图。

现在角标不再自己猜，而是**问绘制层实际用了哪条路**（`painters.resolve_source`，
绘制与角标同一个判定）：

| 实际画法 | 角标 | 状态栏/诊断措辞 |
|---|---|---|
| 脚本现造皮肤 | 近似 | 按代码皮肤绘制（静态索引推断） |
| ui.lst 的 `iStyle` 配色 | 近似 | 图片不可用，按样式表配色绘制（`RENDER_STYLE_SKIN`） |
| 无图也无 `iStyle` 颜色 | 模拟 | 底色是编辑器默认色 |
| 切片 / 整图 / 帧 | 原生 / 近似 | 与 0.12.0 相同 |
| 真的什么都没画出来 | 模拟「占位」 | 目录型基路径会说明「没拼出任何切片族」 |

另外两处顺带修好：

- `CTextButton` 的目录型基路径（如 `combdialog4\三态按钮\一级按钮\`）以前
  走「整图拉伸」的近似拼法，现在和其它框类一样按**切片**拼，角标转「原生」；
- `CButton` 家族在图片取不到时也会用 `iStyle` 的常态色（有才用），不再一律
  画编辑器默认灰蓝。

```
改 iStyle 0 → 1：按钮颜色变（像素证实），角标始终是「近似」，不再是「占位」
```

## 0.12.0：画布原生还原度——切片按资源切割线、保真度角标、运行时隐藏

三件事都围绕同一个风险：**编辑器看着对、客户端不一定这样**。所以这版把
「有实据的画法」和「编辑器猜的画法」在画布上分开标出来，不再混在一起。

### 1. 切片改按资源自己的切割线（不再是固定三等分）

以前九宫格不管图怎么切，一律三等分——四角被拉变形，边也被拉。

现在：目录型资源（`sFileName` 以 `\` 结尾）里的横三片 / 竖三片 / 九片，
**切割线就是这些切片文件本身的像素尺寸**：

| 族 | 拼法 | 依据 |
|---|---|---|
| 横三片 `left1.png`+`middle.png`+`right2.png` | 左右按各自像素宽固定，中间吃剩余宽度；三块按控件高纵向拉伸 | 反编译 `combdialog.py` 的 `CreatePngHFrame_New` 字面量 + 切片真实尺寸 |
| 竖三片 `top`/`middle`/`bottom` | 上下按各自像素高固定，中间吃剩余高度 | 同上（竖框族） |
| 九片 `top/left.png` … `bottom/right.png` | 四角原样、四边单向拉伸、中心双向拉伸；列宽取该列最大像素宽、行高取该行最大像素高 | `top/left%s`/`middle%s` 字面量 + 切片真实尺寸（**中列名字已按 0.12.5 实测修正为 `*/middle`**） |

另外：

- 目标尺寸放不下四角时按比例缩小两端（不出现负尺寸、不越界）；
- **整块全透明的切片不绘制**（不铺白底，底下内容照常露出）；
- 单图九宫格（`CPngNineFrame` 只给一张图）仍然只能固定三分——`.dlg` 没有
  切割线字段，这条**明确标「近似」**，不装作原生。

### 2. 画布保真度角标：原生 / 近似 / 模拟

控件右下角会出现小角标（原生不标，不打扰视线）：

| 档 | 颜色 | 什么时候出现 |
|---|---|---|
| 近似 | 橙 | 单图九宫格固定三分、整图拉伸到控件尺寸、按帧序推断按钮状态、`.spr` 只画当前帧 |
| 模拟 | 红 | 缺图占位框、按下/悬停/禁用的压暗提亮灰化 |

状态栏右端常驻一句说明（选中控件时更新），诊断面板另有对应提示。
动画/按钮里凡「顺序靠推断」的，一律说「顺序未与客户端核实」。

### 3. 运行时隐藏 ≠ 资源加载失败

- `bShow=0`（布局里有、进游戏不显示）：画布照常画，但**压暗 + 虚线框 +
  角标「运行时隐藏 bShow=0」**；诊断报 `RUNTIME_HIDDEN`（提示）。
- `bLoad=0`：角标「bLoad=0 可能不加载」；诊断报 `RUNTIME_NOT_LOADED`（提示），
  措辞保留「语义未与客户端核实」。
- 缺资源的红框占位仍报 `RESOURCE_MISSING`（警告）。三者互不吞并，同一个控件
  可以同时既有 `RUNTIME_HIDDEN` 又有 `RESOURCE_MISSING`。

字段写法兼容 `true/false`、`0/1`、`"0"/"1"`、单元素列表；字段缺失按「显示」
处理，不当成隐藏。

### 4. 顺带修掉一个真 bug：状态栏常驻标签从来没显示过

`MainWindow.__init__` 里 `setStatusBar(QStatusBar())` 在工具栏之后执行，把
工具栏刚挂上常驻标签（缩放百分比）的旧状态栏整条销毁——所以缩放百分比一直
不显示。现在状态栏先建，标签正常常驻。

### 5. 真实样本统计工具

`ui_editor/tools/interface_probe.py` 新增两段（只读、无 Qt）：

- 切片尺寸：逐条切片族打印各块的**真实像素尺寸**（切割线的证据来源）；
- 按钮状态摸底：统计 `sDownImageName`/`sMouseOverImageName`/
  `sDisabledImageName`/`sCheckedImageName` 在真实布局里出现多少次，以及
  「图高 / 控件高」的比例分布（竖条多态的直接证据）。

拿 interface.fls 跑一次就能知道真实数据里到底有没有显式状态字段；
**这一版没有猜状态顺序**，跑完再按数据定映射。

## 0.11.2：对齐不出父、非法图名当场提示、保存不擅自建目录

### 对齐 / 等距分布：结果夹回父控件（画布变化）

此前对齐与等距分布直接按基准控件算新坐标就落地，不检查父边界：

图不会被挂账，也不会有半截状态。

原来保存到 `D:\mxsj\新建文件夹\a.dlg` 时会**自动把目录建出来**再保存，

## 0.10.6：画布右键「导出素材」——什么格式就什么格式

**画布／菜单变化**（面板布局不变）。此前只能整包发布，没法单独把某个
控件用的图片、精灵、音效拿出来看或改。

在画布上右键控件 → **导出素材**，有两个入口：

| 菜单项 | 行为 |
|---|---|
| 按原格式导出… | 包里存的是什么格式就导出什么格式：PNG/JPEG/GIF/BMP/TGA/WAV/OGG/MP3 原字节写出；游戏精灵（I0/T0/I1/T1/T4/T5）沿用原资源名（`.igs`／`.png` 等，游戏按此名加载）；认不出的格式保留原扩展名、字节原样──**绝不擅自转成 PNG** |
| 转成图片导出（精灵逐帧 PNG）… | 想直接用看图软件打开时用：精灵解成逐帧 PNG，真图片仍原样 |

细节：

- 控件四个素材字段都会导出：`sFileName`、`sBgFileName`（进度条底图）、

- `.spr`（帧时表）导出时**连带**导出它指名的帧图源文件；`.spr` 本身按原字节写；
- 多选后右键：把所选控件的素材一起导出到同一个文件夹；
- 重名自动加序号（`btn.png`、`btn-2.png`），不覆盖目标文件夹里的既有文件；
  仍然拒绝覆盖游戏包内的源资源（`guard_output`）；
- 资源包内找不到的资源会在状态栏点名提示，不会静默失败或造空文件；
- 多选/单击都可用；所选控件都没有素材时子菜单显示灰色提示。

## 0.10.5：颜色选择器加「吸管」（从屏幕取色）

**面板变化**（画布不变）。此前颜色对话框用的是 Windows **原生**颜色对话框，
它没有屏幕吸管，只能手输色值。

现在：

- 每个颜色（标量一行、列表每组各一个）旁边多一个 **💧 吸管按钮**：点它
  直接打开颜色对话框并**自动进入吸管取色状态**，鼠标变成十字，点到屏幕上
  任何位置（包括编辑器外的窗口、网页、图片）即取该点颜色；
- 颜色对话框改为 **Qt 自带实现**（`DontUseNativeDialog`）——原生 Windows

## 0.10.4：复制粘贴自动重命名（BTN → BTN_1 → BTN_2）

**编辑行为变化**（画布、面板布局不变）。此前粘贴保留原名，副本与原控件
同名，既会让诊断里出现重复名，也可能让脚本的 `sName` 认领指到副本上。

现在粘贴时：

| 操作 | 结果 |
|---|---|
| 复制 `BTN` → 粘贴 | `BTN_1`（原件还在，重名） |
| 再粘一次 | `BTN_2` |
| 复制 `BTN_1` → 粘贴 | `BTN_1_1`，再粘 `BTN_1_2` |
| 一次粘一组 | 各自按同样规则取不重名的名字（`BTN_1`、`BTN2_1`…） |
| 子树里的重名子控件 | 一并改名（`txt` → `txt_1`），原件子树不受影响 |
| 名字不重名（如原件已删除后再粘） | 保持原名 |

- 整次粘贴仍算**一步撤销**。
- 说明：改名只发生在粘贴这一刻，之后可以照常在属性面板改成想要的名字
  （改名仍会走脚本引用护栏）。

## 0.10.3：可以从锁定控件上按住拖动框选（锁定区域=空白画布）

**画布交互变化**（绘制、面板布局无变化）。0.10.2 让锁定控件点不到，但
在它上面按下会穿透到下面的父控件，于是拖起来是**拖父控件**，没法从那
块区域起手框选。

现在锁定控件所占的那块区域**当作空白画布**：

- 在锁定控件上**按住拖动** → 拉出选框，选到框里的其他（未锁定）控件，
  不会去拖它下面的父控件；
- 在锁定控件上**单击不拖** → 仍然穿透到下面那一层（选中父控件/底图），
  与 0.10.2 一致；
- 右键仍在锁定控件上穿透到下一层（菜单作用于下层控件）；
- 锁定控件自身永远选不中（框也框不进来）。

**取舍**：如果某个未锁定的控件正好被锁定控件整块盖住，从被盖住的位置
按下去会是框选而不是拖那个控件——挪到它露出来的位置再拖即可。空格/中键
平移不受影响。

## 0.10.2：锁定控件在画布上完全无视（点不到）

**画布交互变化**（绘制、面板布局无变化）。之前锁定只是「拖不动、缩不了、
删不掉」，但仍可在画布上点中它来解锁；用户要求「画布中完全无视它、
完全点不到」。

现在锁定后：

- **点不到**：图元不接收任何鼠标键，按下直接**穿透到下面的控件**
  （所以在锁定的按钮上点一下，选中的是它背后的父控件/底图）；
- **选不中**：去掉可选标志，`setSelected()` 也不生效，不画选中虚线框与
  resize 把手；
- **框选不到**：空白处拖框不会把它选进来；
- **右键也不认它**：右键命中会跳过锁定控件，落到下一层；
- **拖不动/缩不了/删不掉/对齐分布绕开**：与之前一致；
- **吸附也不参考它**：拖动吸附只用未锁定的同级控件与父边缘，锁定控件
  不再产生吸附参考线（要它当参照就先解锁）；
- **仍然照常绘制**，右上角挂锁徽标保留，一眼能看出这块锁着。

**解锁方式**：左侧控件树的锁图标（第 2 列）——点一下即解锁；锁定控件的
属性面板照常能看（从控件树选中时只更新面板、不进画布选择）。父控件锁定
仍不影响子控件，子控件可以单独拖动/缩放。

## 0.10.1：颜色选择器支持列表颜色（真实布局的主力写法）

**面板变化**（画布不变）：0.10.0 的取色器只接了标量属性，但真实 `.dlg`
里颜色几乎都是列表——原生属性面板把颜色当 `iType 5`，`Code2Color`
生成 3/6/9 个整数（1~3 组 RGB）。实测本仓库真实布局：`lColor` 3 个数
13 处、6 个数 12 处、9 个数 5 处，`lNormalColor` 3 个数 1 处。所以打开
真实布局时看不到色块。

现在：

- `lColor`/`lNormalColor`/`lEnterColor` 等**列表颜色**逐组显示色块
  （3 个数 1 个色块、6 个数 2 个、9 个数 3 个），点任一色块改对应那组
  RGB，其余组不动；写回**保持 list/tuple 类型与长度**（实测
  「选色 → 序列化 → 重新解析」值完全一致）。

  退回普通序列编辑器（不猜语义）。
- 标量颜色（`iColor` 整数、`"255,0,0"`、`#RRGGBB`）行为不变。

**顺带修**：0.10.0 里「父内夹取」用了 `iWidth/iHeight` 原值，遇到宽高为
0（靠图片撑开）的父控件会把子控件压成 8×8 / 贴到左上角。现在统一用

尺寸未知时不夹取，只保证坐标非负。

   例如 `login/regform.dlg`。只列已识别且在该包内的布局；拒绝本地绝对地址、
   `.`/`..`、空段、非法字符、非 `.dlg` 后缀和不能按 GBK 编码的地址。
3. 通过受限解析与 Big5 显示文本/GBK 资源字段检查后，已有布局需确认替换；
   目标不是布局则拒绝。取消/失败保留当前文档。当前文档未保存时仍需确认丢弃。
4. 导入后显示「待入新包」树节点，可预览编辑；一次仅一个待入包布局，不是
   多文件队列。切换/放弃即清掉待入包节点，不把它冒充源包里的真实条目。
5. 「文件 → 保存回资源包（生成新包）」显示新增/替换布局清单。成功后挂载
   并优先使用新包；自定义地址会保存在**本机应用设置**，下次启动仍按包内编号核对显示。
   0SLF 自身仍无法恢复全名，换电脑时可用“按包内路径打开布局”找回。
   连续导入多份布局时，先保存上一份，再在**生成的新包节点**导入下一份；
   不要反复在旧包节点各自生成副本，否则各个副本不会自动合并。

**原包不动，不自动带图片，不自动接脚本。** 0.8.3 起新增/替换均按已核实的
原生路径 XOR 密钥存储。旧版本的明文/零密钥策略有误，不能当作原生兼容。
只读打开仍兼容旧存储，保存当前布局会迁移，之后可正常重开/继续调整。
合成包独立回读/目录升序/非零种子/未改条目逐字节检查已覆盖；**新布局的
客户端原生加载、Windows 桌面/EXE 与完整语料库仍待验**，只在游戏副本测试。

## 0.8.0：编辑前护栏与保存前检查

- **改名在写入属性前检查**：静态索引发现原名字被按名取用、作为位置锚点或
  代码皮肤时，列模块/entry/类/方法并默认取消。新增属性覆盖 `sName` 也走
  同一护栏；核心名字字段不能删。改成重复名或非字符串会拒绝；粘贴保留原名
  的既有行为不改，重复名由诊断列出。确认改名后不会改写脚本或自动接线。
- 删除检查覆盖**整棵待删除子树**，不是只看选中的父控件。已锁定子树仍受
  保护；取消不改文档、不增加撤销步，确认后的删除可撤销/重做。
- 窗口底部「布局诊断（静态）」或 `Ctrl+Shift+D` 刷新：检查重复名、负数/非
  整数尺寸、零尺寸提示、相对父矩形越界、当前挂载资源缺图/缺音、待入包图、
  字段编码与静态引用缺控件。点击结果按树位置定位，重复名不误选第一项；
  编辑后结果标过期、暂停定位，刷新后恢复。警告可标为本次有意设计，不进
  `.dlg`；刷新与保存检查仍完整列出，编码错误不能隐藏/强行确认保存。
- 保存/另存散装布局和生成新包前列出**相对最近成功保存基线**的控件增删、
  字段旧值/新值、图片新增/替换/未引用跳过与全部诊断；布局按树位置比较，
  重排/移动会表现为对应位置的字段差异。未知原生字段同样保留并列入清单。
  散装 `.dlg` 不嵌入图片，待入包资源不会提前销账。取消/失败不重设基线，
  成功保存才重设；UI 仍保留原撤销时间线，撤销到不同于已保存状态会标脏。
- **原生编码护栏**：Big5 显示字段、GBK 路径无法编码时禁止 GUI 确认保存，
  程序化 `write_pack_copy()` 也在写入前拒绝；不做自动简繁转换，不把 codec 的
  GB18030 兼容回退冒充引擎支持。原始 surrogateescape 字节仍允许保真往返。
  新建布局默认标题使用可编码的「新對話框」。
- 边界：没有挂载资源不判「缺图」，没有静态命中不代表没有动态引用；零尺寸
  可能取图片/样式，越界可能是滚动/重叠设计。诊断只检查当前挂载来源，保存
  新包后尚未重挂的资源也可能被提示未找到。**静态检查不能替代游戏实机。**
  本版不修改 `script.fls`、不增加脚本编译/自动接线/包外项目格式。

## 0.7.1 起继续有效的保存/导出安全约定

- 写包一律生成新包：拒绝源包、已挂载包以及它们的同路径、硬链接、
  符号链接别名，不再提供确认后直接覆盖原包的分支。
- 在唯一临时副本上打补丁，发布前回读布局/新图，并对所有未改条目
  分块逐字节比较；偏移和长度不变不能代替负载校验。
- 构建、附加资源写入、校验或原子发布失败时，源包和旧输出都不动，
  临时文件清理；大包保存会增加全量读取校验开销，但不全量载入内存。
- 散装另存、画布 PNG 和选图窗资源导出同样拒绝覆盖已挂载资源包；
  另存失败保留原文档关联和脏状态，多帧导出先检查全部目标。

## 使用流程

* **打开现有布局（散装）**：「文件 → 打开布局文件」选 `.dlg`，
  或「打开布局目录」把散装目录挂到左侧资源树后双击（解码出的
  `interface_dlg_decoded/` 目录可直接打开）。
* **打开现有布局（包内）**：「文件 → 从资源包打开布局」直接选
  `.fls` 包文件即可（没有已识别布局的包也入树，可右键导入）；或「从资源
  目录打开布局」选客户端 data 目录（无布局的包会自动跳过）。
  包会留在左侧资源树上（下挂其布局），在树上方输入名称可快速
  查找，双击布局即可切换；`ui.lst` 自动加载为样式表。
* **资源树与代际标记**：布局按代际着色（绿=现役新 UI: dialog4/login_new/新系统目录，橙=第三代 dialog3，灰色斜体=内置目录里有但该包内缺失的死引用/热更新项）；打开过的资源包会留在左侧资源树上（下挂
  布局），打开动作本身即挂载；图片按引擎路径哈希跨包查找
  绘制，缺图时显示占位框（标注文件名），不影响编辑。
* **编辑**：画布上点选控件、拖动改位置、拖选中框把手改尺寸；
  右侧属性面板按类型改任意字段（可增删自定义字段）；左侧控件
  树管理层级与绘制顺序；右侧下方调色板双击添加新控件（38 种，
  默认属性取自 47,139 个真实控件的普查模板）。
* **新建布局**：「文件 → 新建布局」得到空白主窗口起步。
* **保存**：写回原版式 `.dlg` 文本；从包打开的布局可用「文件 → 保存回资源包（生成新包）」把改动写进一个新 `.fls`（原包不动、逐条校验通过才提示安装）（文件头保留 `# -*- coding: gbk -*-`；显示文本为 Big5、资源路径为 GBK 的混合编码，编辑器按字段编解码）
  头、list/tuple/bool 保型）。一期只写散装文件，不回写包内。
* **导出 PNG**：「文件 → 导出 PNG」把当前布局渲染成图对照。

## 格式与保真约定

* 语料测试分两层（`tests/test_codec.py`）：**仓库内自带的最小语料恒跑**
  ——`tools/registration/` 的 7 个真实布局 + 本包夹具，走「解析 → 序列化 →
  再解析」结构一致性；**外部大语料**只在给了 `MXSJ_DLG_CORPUS`（目录，
  支持多个用 `:` 分隔）时跑，结果**按实际数量上报**，不再硬编码开发沙箱
  路径、也不再把「语料少于 2,000 篇」直接判失败（那会让一条测试连
  手里的 7 篇都不跑，见 `docs/analysis/ui_editor_analysis_20261016.md` P1-4）。
  真 `interface.fls` 与全量语料从用户指定的 Drive 目录取（**目录会随开发更新，先列目录再看**），
  校验与解压命令见 [`docs/EXTERNAL_CORPUS.md`](../docs/EXTERNAL_CORPUS.md)。
* 共享核心：路径哈希、`.dlg` 原生存储、输出路径保护、精灵格式常量都在
  仓库 `mx_common/`（唯一真源），本包 `core/` 下同名文件是
  `tools/devkit/vendor_core.py` 生成的字节副本，**不要手改**；改真源后跑
  `python3 tools/devkit/vendor_core.py --write`，`--check` 应当 0 报告。
* **写回时目标条目自身的字节会变**：编辑器按自己的序列化版式重写
  （字段顺序与写法归一化——实测 8 个真实 `.dlg` 里只有 1 个「解析→
  序列化」逐字节相同，见 `docs/analysis/ui_editor_analysis_20261016.md`
  P2-1）；旧明文/旧密钥存储在保存时同时迁移为原生路径密钥。所以
  「未改条目逐字节保护」**不覆盖目标条目**：除目标条目、本次写入的
  图片与明确迁移的旧存储外，其它条目逐字节不动。保存清单首行会写明
  本条目属于哪一种（新增 / 旧存储迁移 / 版式按编辑器序列化重写 /
  字节不变），保存成功弹窗同样带这句。
* 尺寸：`iWidth/iHeight` 为正用之，为 0 取图片首帧尺寸
  （`CImagesFrame` 按行列推算）；坐标相对父控件。
* 绘制是编辑用近似渲染：图片画首帧、文字按钮按 `ui.lst`
  的 TBStyle 着色、文字按 `iFont` 字体表绘制。九宫格目前只有
  `CPngNineFrame` 的**固定三分**近似（边角不拉伸、边与中心拉伸，
  切割线不可配、未与游戏切法比对）；M3.3 的切割线编辑与数据摸底
  仍未做，`notes/ui_editor_phase2_design.md` §2.3 的范围不变。

## 绘制对照清单（编辑器 vs 真机）

绘制是最像游戏、也最容易「看起来对」的一层：单测只能证明不崩、尺寸对，
**证明不了外观一致**。所以这里不改判定方式，只把材料准备好：

```bash
# 1. 渲染 38 类控件样例（写到仓库外；--image/--assets-dir 可指向真实客户端资源）
python3 ui_editor/tools/render_paint_samples.py --out /tmp/paint_samples \
        --pack <interface.fls> --image "combdialog4\\...\\底板800.png"
# 2. 真机截图后比对（给统计，不给结论）
python3 ui_editor/tools/paint_compare.py \
        --editor /tmp/paint_samples/CButton.png --game shot.png --out /tmp/paint_cmp
```

* 输出：每个类型一张 PNG、`contact_sheet.png` 联络表、`manifest.json`（尺寸 +
  SHA256 + 该类型走哪个绘制函数 + 是否命中真实资源）；
* 结论填进 [`docs/PAINT_CHECKLIST.md`](docs/PAINT_CHECKLIST.md)：**没做过真机
  核对的格子必须留空**，不许预填「一致」（`tests/test_paint_samples.py` 会
  机检这条规矩、清单与代码的类型/函数一致性、以及 38 类全部渲染不崩）。
* 仓库内**没有**界面图资源（`interface.fls` 未入库），所以不给
  `--image/--assets-dir` 时样例走「缺资源占位框」分支——这本身就是要核对的
  一列；给了真实资源才会走图片/精灵解码。

`build_exe.bat`（纯 ASCII、CRLF）依次：探测 `py -3`/`python` → 建或复用 `.venv` →
`pip install -r requirements-dev.txt` → 跑全部 `unittest`（`PYTHONPATH=src`、
`QT_QPA_PLATFORM=offscreen`，不通过就不出包）→
`python -m PyInstaller --noconfirm --clean ui_editor.spec`。入口是轻量的 `run.py`
（不装依赖、不自检；日常仍用 `启动UI编辑器.bat`）；spec 把
`src/ui_editor/data/known_layouts.txt` 打进 `ui_editor/data/`，与 `core/catalog.py`
的 `Path(__file__).parent.parent / "data"` 查找方式一致；`console=False`，双击直接开窗。

> 流程与 [`docs/PYTHON_TOOL_CONVENTIONS.md`](../docs/PYTHON_TOOL_CONVENTIONS.md) §4
> 一致。PyInstaller 不能跨平台：Linux 沙箱只做了 spec 干跑（onedir / onefile 都能
> 完整构建出 Linux 产物，数据文件落位正确），**`.exe` 尚未在 Windows 上实际构建和
> 双击验收**（STATUS §3.5）。
