# MXSJ UI 编辑器（ui_editor）

可视化编辑梦想世界客户端 UI 布局（`.dlg`）的独立工具：能打开
现有布局修改，也能从空白新建布局。布局格式、路径哈希、包内
解密均来自本仓库的逆向结案成果（见 `notes/fls_path_hash_and_dlg.md`）。

当前版本：**0.8.3**（新增包树右键布局导入，保留引用护栏/诊断/保存清单）。

## 0.8.3：正常编辑流程按原生路径加密

- 任意新 .dlg 路径新增、已有布局修改/再次保存，都按完整路径哈希派生的原生
  XOR 密钥写入。不是注册两路径特例，也不需要手工加密/运行一次性修复器。
- 旧版明文/错误密钥可只读打开；明确“保存回资源包”时迁移当前布局，即使
  不改属性也能重新生成新包。未打开/未保存的其它布局不会偷偷改。
- 新包发布前使用游戏的路径密钥解密比对当前布局，不再仅靠从输出头反推密钥
  的编辑器自洽校验；校验失败源包与既有输出不动。
- 新增→保存→重开→继续修改→再保存已补连续回归，含重组回退、错误密钥迁移
  和错误输出拒绝。Big5文案/GBK路径规则、撤销、路径记忆、新包接续均保留。
- 散装 .dlg 仍是可编辑明文，入包才自动加密。仍无自动脚本接线/多布局队列。
  离线通过不代表 Windows/游戏加载已验收，新增布局的使用还要有对应脚本入口。

## 0.8.2：保存重开找回路径

- 修复 0.8.1 自定义布局只在当前会话登记的问题：成功生成新包/成功按路径
  回读后，将真实地址存入应用设置，下次启动再按编号与实际包内容相交入树。
  不改包格式、不增加包外项目文件、不编造未知名字；这是本机设置，换电脑
  或删除设置不会带走自定义字典。
- 旧版已经写入但树里找不到：打开**保存生成的新包**，右键包根选择
  **“按包内路径打开布局…”**，输入当时导入的精确地址。只读回查，不再次
  导入/写包；成功后显示到树并记住地址。找不到时不会挂幽灵节点。
- `login/regform.dlg` / `login/regterms.dlg` 加入已知字典，旧版写入这些
  完整地址的包也能重新识别。`regform.dlg` 与 `login/regform.dlg` 是不同
  地址，不会自动改写或把二者当同一条目。
- 文件变大/大小一致不能证明布局被正确写入；仍须精确路径回读比对。

## 0.8.1：资源包右键导入布局

1. 在左侧资源树的 `.fls` **包根节点**右键「导入布局文件…」。没有已识别布局
   的 0SLF 包也会入树（不是所有 `.fls` 格式都支持）。
2. 选择本地明文 `.dlg`，在可搜索/手填下拉中选已有地址或填完整新地址，
   例如 `login/regform.dlg`。只列已识别且在该包内的布局；拒绝本地绝对地址、
   `.`/`..`、空段、非法字符、非 `.dlg` 后缀和不能按 GBK 编码的地址。
3. 通过受限解析与 Big5 显示文本/GBK 资源字段检查后，已有布局需确认替换；
   目标不是布局则拒绝。取消/失败保留当前文档。当前文档未保存时仍需确认丢弃。
4. 导入后显示「待入新包」树节点，可预览编辑；一次仅一个待入包布局，不是
   多文件队列。切换/放弃即清掉待入包节点，不把它冒充源包里的真实条目。
5. 「文件 → 保存回资源包（生成新包）」显示新增/替换布局清单。成功后挂载
   并优先使用新包；自定义地址会保存在**本机应用设置**，下次启动仍按包内编号核对显示。
   0SLF 自身仍无法恢复全名，换电脑时可用“按包内路径打开布局”找回。
   连续导入多份布局时，先保存上一份，再在**生成的新包节点**导入下一份；
   不要反复在旧包节点各自生成副本，否则各个副本不会自动合并。

**原包不动，不自动带图片，不自动接脚本。** 0.8.3 起新增/替换均按已核实的
原生路径 XOR 密钥存储。旧版本的明文/零密钥策略有误，不能当作原生兼容。
只读打开仍兼容旧存储，保存当前布局会迁移，之后可正常重开/继续调整。
合成包独立回读/目录升序/非零种子/未改条目逐字节检查已覆盖；**新布局的
客户端原生加载、Windows 桌面/EXE 与完整语料库仍待验**，只在游戏副本测试。

## 0.8.0：编辑前护栏与保存前检查

- **改名在写入属性前检查**：静态索引发现原名字被按名取用、作为位置锚点或
  代码皮肤时，列模块/entry/类/方法并默认取消。新增属性覆盖 `sName` 也走
  同一护栏；核心名字字段不能删。改成重复名或非字符串会拒绝；粘贴保留原名
  的既有行为不改，重复名由诊断列出。确认改名后不会改写脚本或自动接线。
- 删除检查覆盖**整棵待删除子树**，不是只看选中的父控件。已锁定子树仍受
  保护；取消不改文档、不增加撤销步，确认后的删除可撤销/重做。
- 窗口底部「布局诊断（静态）」或 `Ctrl+Shift+D` 刷新：检查重复名、负数/非
  整数尺寸、零尺寸提示、相对父矩形越界、当前挂载资源缺图/缺音、待入包图、
  字段编码与静态引用缺控件。点击结果按树位置定位，重复名不误选第一项；
  编辑后结果标过期、暂停定位，刷新后恢复。警告可标为本次有意设计，不进
  `.dlg`；刷新与保存检查仍完整列出，编码错误不能隐藏/强行确认保存。
- 保存/另存散装布局和生成新包前列出**相对最近成功保存基线**的控件增删、
  字段旧值/新值、图片新增/替换/未引用跳过与全部诊断；布局按树位置比较，
  重排/移动会表现为对应位置的字段差异。未知原生字段同样保留并列入清单。
  散装 `.dlg` 不嵌入图片，待入包资源不会提前销账。取消/失败不重设基线，
  成功保存才重设；UI 仍保留原撤销时间线，撤销到不同于已保存状态会标脏。
- **原生编码护栏**：Big5 显示字段、GBK 路径无法编码时禁止 GUI 确认保存，
  程序化 `write_pack_copy()` 也在写入前拒绝；不做自动简繁转换，不把 codec 的
  GB18030 兼容回退冒充引擎支持。原始 surrogateescape 字节仍允许保真往返。
  新建布局默认标题使用可编码的「新對話框」。
- 边界：没有挂载资源不判「缺图」，没有静态命中不代表没有动态引用；零尺寸
  可能取图片/样式，越界可能是滚动/重叠设计。诊断只检查当前挂载来源，保存
  新包后尚未重挂的资源也可能被提示未找到。**静态检查不能替代游戏实机。**
  本版不修改 `script.fls`、不增加脚本编译/自动接线/包外项目格式。

## 0.7.1 起继续有效的保存/导出安全约定

- 写包一律生成新包：拒绝源包、已挂载包以及它们的同路径、硬链接、
  符号链接别名，不再提供确认后直接覆盖原包的分支。
- 在唯一临时副本上打补丁，发布前回读布局/新图，并对所有未改条目
  分块逐字节比较；偏移和长度不变不能代替负载校验。
- 构建、附加资源写入、校验或原子发布失败时，源包和旧输出都不动，
  临时文件清理；大包保存会增加全量读取校验开销，但不全量载入内存。
- 散装另存、画布 PNG 和选图窗资源导出同样拒绝覆盖已挂载资源包；
  另存失败保留原文档关联和脏状态，多帧导出先检查全部目标。

## 快速开始

1. Windows：双击 `启动UI编辑器.bat`（自动检查/安装 Python
   依赖 PySide6，然后打开界面）；
2. 命令行：`python bootstrap.py [布局文件|目录|资源包]`；
3. 已装依赖时也可：`PYTHONPATH=src python -m ui_editor`。

## 使用流程

* **打开现有布局（散装）**：「文件 → 打开布局文件」选 `.dlg`，
  或「打开布局目录」把散装目录挂到左侧资源树后双击（解码出的
  `interface_dlg_decoded/` 目录可直接打开）。
* **打开现有布局（包内）**：「文件 → 从资源包打开布局」直接选
  `.fls` 包文件即可（没有已识别布局的包也入树，可右键导入）；或「从资源
  目录打开布局」选客户端 data 目录（无布局的包会自动跳过）。
  包会留在左侧资源树上（下挂其布局），在树上方输入名称可快速
  查找，双击布局即可切换；`ui.lst` 自动加载为样式表。
* **资源树与代际标记**：布局按代际着色（绿=现役新 UI: dialog4/login_new/新系统目录，橙=第三代 dialog3，灰色斜体=内置目录里有但该包内缺失的死引用/热更新项）；打开过的资源包会留在左侧资源树上（下挂
  布局），打开动作本身即挂载；图片按引擎路径哈希跨包查找
  绘制，缺图时显示占位框（标注文件名），不影响编辑。
* **编辑**：画布上点选控件、拖动改位置、拖选中框把手改尺寸；
  右侧属性面板按类型改任意字段（可增删自定义字段）；左侧控件
  树管理层级与绘制顺序；右侧下方调色板双击添加新控件（38 种，
  默认属性取自 47,139 个真实控件的普查模板）。
* **新建布局**：「文件 → 新建布局」得到空白主窗口起步。
* **保存**：写回原版式 `.dlg` 文本；从包打开的布局可用「文件 → 保存回资源包（生成新包）」把改动写进一个新 `.fls`（原包不动、逐条校验通过才提示安装）（文件头保留 `# -*- coding: gbk -*-`；显示文本为 Big5、资源路径为 GBK 的混合编码，编辑器按字段编解码）
  头、list/tuple/bool 保型）。一期只写散装文件，不回写包内。
* **导出 PNG**：「文件 → 导出 PNG」把当前布局渲染成图对照。

## 格式与保真约定

* 语料测试分两层（`tests/test_codec.py`）：**仓库内自带的最小语料恒跑**
  ——`tools/registration/` 的 7 个真实布局 + 本包夹具，走「解析 → 序列化 →
  再解析」结构一致性；**外部大语料**只在给了 `MXSJ_DLG_CORPUS`（目录，
  支持多个用 `:` 分隔）时跑，结果**按实际数量上报**，不再硬编码开发沙箱
  路径、也不再把「语料少于 2,000 篇」直接判失败（那会让一条测试连
  手里的 7 篇都不跑，见 `docs/analysis/ui_editor_analysis_20261016.md` P1-4）。
* 共享核心：路径哈希、`.dlg` 原生存储、输出路径保护、精灵格式常量都在
  仓库 `mx_common/`（唯一真源），本包 `core/` 下同名文件是
  `tools/devkit/vendor_core.py` 生成的字节副本，**不要手改**；改真源后跑
  `python3 tools/devkit/vendor_core.py --write`，`--check` 应当 0 报告。
* **写回时目标条目自身的字节会变**：编辑器按自己的序列化版式重写
  （字段顺序与写法归一化——实测 8 个真实 `.dlg` 里只有 1 个「解析→
  序列化」逐字节相同，见 `docs/analysis/ui_editor_analysis_20261016.md`
  P2-1）；旧明文/旧密钥存储在保存时同时迁移为原生路径密钥。所以
  「未改条目逐字节保护」**不覆盖目标条目**：除目标条目、本次写入的
  图片与明确迁移的旧存储外，其它条目逐字节不动。保存清单首行会写明
  本条目属于哪一种（新增 / 旧存储迁移 / 版式按编辑器序列化重写 /
  字节不变），保存成功弹窗同样带这句。
* 尺寸：`iWidth/iHeight` 为正用之，为 0 取图片首帧尺寸
  （`CImagesFrame` 按行列推算）；坐标相对父控件。
* 绘制是编辑用近似渲染：图片画首帧、文字按钮按 `ui.lst`
  的 TBStyle 着色、文字按 `iFont` 字体表绘制。九宫格目前只有
  `CPngNineFrame` 的**固定三分**近似（边角不拉伸、边与中心拉伸，
  切割线不可配、未与游戏切法比对）；M3.3 的切割线编辑与数据摸底
  仍未做，`notes/ui_editor_phase2_design.md` §2.3 的范围不变。

## 绘制对照清单（编辑器 vs 真机）

绘制是最像游戏、也最容易「看起来对」的一层：单测只能证明不崩、尺寸对，
**证明不了外观一致**。所以这里不改判定方式，只把材料准备好：

```bash
# 1. 渲染 38 类控件样例（写到仓库外；--image/--assets-dir 可指向真实客户端资源）
python3 ui_editor/tools/render_paint_samples.py --out /tmp/paint_samples \
        --pack <interface.fls> --image "combdialog4\\...\\底板800.png"
# 2. 真机截图后比对（给统计，不给结论）
python3 ui_editor/tools/paint_compare.py \
        --editor /tmp/paint_samples/CButton.png --game shot.png --out /tmp/paint_cmp
```

* 输出：每个类型一张 PNG、`contact_sheet.png` 联络表、`manifest.json`（尺寸 +
  SHA256 + 该类型走哪个绘制函数 + 是否命中真实资源）；
* 结论填进 [`docs/PAINT_CHECKLIST.md`](docs/PAINT_CHECKLIST.md)：**没做过真机
  核对的格子必须留空**，不许预填「一致」（`tests/test_paint_samples.py` 会
  机检这条规矩、清单与代码的类型/函数一致性、以及 38 类全部渲染不崩）。
* 仓库内**没有**界面图资源（`interface.fls` 未入库），所以不给
  `--image/--assets-dir` 时样例走「缺资源占位框」分支——这本身就是要核对的
  一列；给了真实资源才会走图片/精灵解码。

## 打包成 EXE（在 Windows 上执行）

```bat
build_exe.bat
:: 产物：dist\UIEditor\UIEditor.exe
:: 单文件版： set UI_EDITOR_ONEFILE=1  然后再跑 build_exe.bat
```

`build_exe.bat`（纯 ASCII、CRLF）依次：探测 `py -3`/`python` → 建或复用 `.venv` →
`pip install -r requirements-dev.txt` → 跑全部 `unittest`（`PYTHONPATH=src`、
`QT_QPA_PLATFORM=offscreen`，不通过就不出包）→
`python -m PyInstaller --noconfirm --clean ui_editor.spec`。入口是轻量的 `run.py`
（不装依赖、不自检；日常仍用 `启动UI编辑器.bat`）；spec 把
`src/ui_editor/data/known_layouts.txt` 打进 `ui_editor/data/`，与 `core/catalog.py`
的 `Path(__file__).parent.parent / "data"` 查找方式一致；`console=False`，双击直接开窗。

> 流程与 [`docs/PYTHON_TOOL_CONVENTIONS.md`](../docs/PYTHON_TOOL_CONVENTIONS.md) §4
> 一致。PyInstaller 不能跨平台：Linux 沙箱只做了 spec 干跑（onedir / onefile 都能
> 完整构建出 Linux 产物，数据文件落位正确），**`.exe` 尚未在 Windows 上实际构建和
> 双击验收**（STATUS §3.5）。
