# 任务书：Windows 观察器运行（给执行 agent）

> 本任务是**只读观察**：用 Frida 挂到你本机自有的游戏副本上，记录函数调用和参数，写入日志。不修改任何游戏文件，不改变游戏行为。
> 你的目标是按顺序完成下面的步骤，并把结果按“第 9 节回报格式”交回。遇到任何停止条件，立即停止并回报，不要自行尝试其他办法。

## 0. 目标与范围（必须遵守）

- **要回答的问题**：
  1. 客户端连接 `127.0.0.1:3134` 时，走的是直连还是代理分支？
  2. 连接之后，客户端有没有调用 `send`？发出的字节数和前几个字节是什么？
  3. `IMProtocol.dll` 的 `IMP_SendBuffer2NS`、`IMP_RefreshCryptKey`、`IMP_ConnectNsServer` 是否被调用？如果被调用，是谁、什么时候调用的（只记录调用顺序和参数形态，见第 7 节）。
- **允许的操作**：启动游戏、运行 Frida 观察器、在游戏中选择**本机**服务器条目、记录日志、截图。
- **禁止的操作**：
  - 修改 `mx.exe`、`mxmain.dll`、`IMProtocol.dll`、`gameplayer.exe`、`DuoyiProtect.dll`、`server.ini`、`mx.ini` 等任何游戏文件；
  - 删除、移动、重命名任何文件；
  - 把观察器文件放进游戏目录（观察器放在 `D:\Lager\观察器\`）；
  - 连接任何外部地址（尤其是 `203.70.8.x`）；
  - 禁用、绕过或修改游戏的保护机制（Duoyi 保护）。如果游戏拒绝运行或检测到调试，**停止并回报**，不要尝试绕过。
  - 把密钥相关的字节内容写进聊天回报或文档（见第 9 节）。

## 1. 前置检查（不通过则停止）

在 `D:\Lager\夢想世界\` 下执行并记录结果：

1. 确认文件存在：`mx.exe`、`mxmain.dll`、`IMProtocol.dll`、`server.ini`。
2. 计算 SHA-256（PowerShell：`Get-FileHash -Algorithm SHA256 <文件>`），与下表比对。**不一致则停止**（说明本机版本与仓库分析的版本不同）。

   | 文件 | 期望 SHA-256 |
   |---|---|
   | `mx.exe` | `637331b54f7fa9fa6c236fa7f9ac8a8b27f228bd46d05046fdccddf52fbe424d` |
   | `IMProtocol.dll` | `bc356c88a6470d761b8976f8c027056b8c0e0f483ca2f59cf5c42542e112c82c` |

3. 确认 `server.ini` 中包含 `127.0.0.1` 条目（这是有意保留的回环配置，不要修改它）。
4. 确认 Python 是 **32 位**。在 cmd 中执行：
   ```
   python -c "import struct; print(struct.calcsize('P')*8)"
   ```
   输出必须是 `32`。输出 `64` 则停止，并回报“需要 32 位 Python”。
5. 确认 Frida 已安装：`python -m pip show frida`。未安装则执行 `python -m pip install frida`，然后再次确认 `pip show frida` 有输出。记录版本号。
6. 确认没有残留的游戏进程：`tasklist | findstr /I "mx.exe gameplayer.exe"`。如果有，**先回报**，不要自行结束进程。

## 2. 准备观察器文件

1. 创建目录 `D:\Lager\观察器\`。
2. 从仓库复制 `notes/observer-20261010/observe.js` 和 `observe.py` 到该目录（仓库内这两个文件是草稿，尚未在 Windows 上运行）。
3. 确认两个文件都在该目录中，文件大小分别约为 95 行和 41 行。

## 3. 启动游戏并确认进程名

1. 双击或在 `D:\Lager\夢想世界\` 下启动 `mx.exe`（不要改任何参数）。
2. 等待窗口出现（可能需要几十秒）。
3. 执行 `tasklist | findstr /I "mx.exe gameplayer.exe"`，记下实际的进程名和 PID。**观察器要挂到实际运行游戏的那个进程上**，如果进程名不是 `mx.exe`，以实际进程名为准，并在回报中说明。
4. 记录启动时间（精确到秒）。

## 4. 启动观察器

1. 打开 cmd，进入观察器目录：
   ```
   cd /d D:\Lager\观察器
   ```
2. 运行（进程名替换为第 3 步确认的名字）：
   ```
   python observe.py mx.exe
   ```
3. 预期输出：
   - `已挂载到 mx.exe，记录写入 observe-log.jsonl。按 Ctrl+C 停止。`
   - 随后若干条 `hooked` 提示（`ws2_32.connect`、`ws2_32.send`，以及 IMProtocol 的导出函数）。
   - 如果 IMProtocol 还没加载，可能暂时没有 IMP 的 `hooked` 提示。等待 30 秒左右，如果仍然没有，记录并继续（见第 6 节的停止条件）。
   - 如果出现 `missing`，记录是哪一个函数。
4. **不要关闭这个窗口**，它会一直运行。

## 5. 复现连接过程

1. 回到游戏窗口。
2. 按屏幕提示进入服务器选择界面。
3. **只选择本机回环条目（`127.0.0.1`，端口 3134）**。如果列表中只出现外部地址（`203.70.8.x`），**不要选择**，停止并回报。
4. 点击连接/登录，等待，直到界面停留在“正在连接服务器…”或出现其他明确状态。
5. 等待约 120 秒，期间每 30 秒截图一次（保存到 `D:\Lager\观察器\screenshots\`，文件名带时间）。
6. 在等待期间，每 30 秒执行一次 `netstat -ano | findstr :3134`，把输出追加到 `D:\Lager\观察器\netstat.txt`，并在每行前写上时间。

> 如果你无法操作游戏界面（例如无法识别按钮），**停止并回报**，写明停在哪个界面。不要猜测点击位置。

## 6. 停止条件（任一满足即停止并回报）

- 游戏弹出安全、保护或调试相关的提示，或直接退出；
- 观察器报错并退出（注意 cmd 窗口中的 Traceback）；
- 观察器日志里出现 `ws2_32.connect` 的目标地址**不是** `127.0.0.1`；
- 只能选择外部服务器，或游戏尝试连接外部地址；
- 第 4 步 IMP 函数 `missing`，且 2 分钟内没有任何 IMP 相关记录（可能是版本不同或时机不对）。

停止时：按 Ctrl+C 结束观察器，**不要结束游戏进程**，除非它已经卡死。回报中写明停止原因。

## 7. 结束与收集

1. 在观察器窗口按 Ctrl+C。确认输出 `已停止。`
2. 收集以下文件到 `D:\Lager\观察器\结果\`（复制，不要移动）：
   - `observe-log.jsonl`（观察器日志）
   - `netstat.txt`
   - `screenshots\` 目录
   - 游戏日志：`log\game\` 下启动时间之后的最新文件（如有）
   - 第 3 步的 `tasklist` 输出
3. 不要修改收集到的任何文件。

## 8. 日志解读（你只需要记录，不要下结论）

`observe-log.jsonl` 每行是一个 JSON 对象，主要字段：
- `event`：`enter` / `leave` / `hooked` / `missing` / `info`
- `fn`：函数名，如 `ws2_32.connect`、`ws2_32.send`、`IMP_SendBuffer2NS`
- `ip`、`port`：仅 `ws2_32.connect` 有
- `len`、`hex`：仅 `ws2_32.send` 有（`hex` 是前最多 128 字节的十六进制）
- `args`：IMP 函数的前 4 个参数，`raw` 为指针或数值，`hex` 为前 128 字节

请在回报中统计：
- 每个函数的 `enter` 次数；
- `ws2_32.connect` 的全部 `ip:port`；
- `ws2_32.send` 的次数、每次 `len`，以及第一次的 `hex` 前 16 字节（仅前 16 字节）；
- 每个 IMP 函数第一次被调用的时间（`host_time`）和相对启动时间的秒数。
