## 4. 名字可信度（需要注意）

“ok” 只表示 **marshal 解析完整 + sanity 过滤通过**（文件名/函数名合法、无大量乱码），**不代表每个名字都正确**。

以 v4-ok 条目的函数名集合作为“干净词表”做校验（`fullrun/decode-results-final.jsonl`）：

| 分组 | 条数 | 说明 |
|---|---|---|
| ok 且全部函数名在词表内 | 4174 | 可信度较高 |
| ok 但含词表外名字 | 310 | 含合法但只在重试条目出现的名字（如 `OpenGameIntegralDlg`），也含仍然乱码的名字（如 `GetWeekPbint`）；需人工核对 |
| 其中：可疑名条目中 v7 重解码仍非 ok，保留 v4 结果 | 11 | `v7_redecode_status` 字段标注 |

详见 `suspicious-names-review.md`：可疑名（179 条）二轮重试后，抽检显示 A 类（55 条，全部名字在词表内）基本正确，B 类（113 条）多数仍有单字节/多字节错误。

## 6. 复现

```bash
# v4 全量（已完成，输出 fullrun/decode-results.jsonl）
python3 tools/fls_batch_decoder.py --archive data/script.fls --all --output <dir> --jobs 2
# v7 二轮：fail+suspect 索引（870）
python3 tools/fls_batch_decoder.py --archive data/script.fls --all --output <dir>/v7-retry --indices <870 个索引，逗号分隔> --jobs 2 --resume
# 可疑名 179 条
python3 tools/fls_batch_decoder.py --archive data/script.fls --all --output <dir>/suspicious-v7 --indices <179 个索引> --jobs 1
```

注：任务书给出的 `--v7-retry` / `--input` 参数在当前 `fls_batch_decoder.py` 中**不存在**；当前版本的解码器即为 v7，重试通过 `--indices` 指定索引完成。
