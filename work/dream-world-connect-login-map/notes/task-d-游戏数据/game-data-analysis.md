## 1. 執行概述與研究目標

本研究圍繞《夢想世界》客戶端中的核心數據歸檔展開，深入破解了封包結構、索引多項式混淆、5段動態 XOR 數據切分，以及多益定製 Python 2.5 Marshal 位元組碼，成功提取出裝備道具、地圖場景、NPC互動、流派招式與獎勵池等全維度結構化數據，並搭建了即時交互式遊戲數據瀏覽器（提供 Web 儀表板與 CLI 終端工具）。

## 2. 客戶端數據歸檔架構

客戶端的核心邏輯與數據資源集中存放於 `data/*.fls` 歸檔之中：

```
data/
├── data.fls        (354 KB, 133 模組, 核心運行時、網路封包解析、字元集編碼庫)
├── script.fls      (24.45 MB, 5,002 模組, 核心遊戲數據字典與客戶端界面邏輯)
├── skill.fls       (1.29 MB, 342 模組, 招式動畫與底層施法數據)
├── skill2.fls      (1.88 MB, 454 模組, 高級技能與召喚獸專屬招式)
├── passive.fls     (105 KB, 41 模組, 被動技能與心法數據)
└── effect.fls      (1.85 MB, 65 模組, 粒子特效與特效觸發關聯)
```

### 2.1 歸檔特徵與加密模型
1. **`data.fls` (ZIP 變體)**:
   - 採用帶有自定義 Magic 簽名 `0x87f2017c` 的連續目錄清單。
   - 文件名採用 `0xA5` XOR 混淆處理。
   - 存儲解密後的 `.pyo` 位元組碼文件，含定製 4 位元組擴展欄位。
2. **`script.fls` / `skill.fls` (0SLF 變體)**:
   - 採用 `0SLF` (四位元組 Magic) 開頭，索引位於文件末尾。
   - 索引項採用 3 階多項式線性變換進行位址與長度混淆。
   - 解壓後的數據體引入了 5 段動態 XOR 切分混淆。

## 3. 核心數據表深入逆向分析

### 3.1 裝備與武器防具體系 (`script\data\equipitemdata.py`)
- **歸檔位置**: Entry 17
- **解壓長度**: 9,732 位元組
- **混淆密鑰**: `[0x63, 0x1d, 0xab, 0x4c, 0x94]`
- **編碼格式**: Big5 (繁體中文)
- **數據涵蓋範圍**:
  - **武器類**: 劍 (短劍、青霜劍)、刀 (短刀、柳葉刀)、槍 (粗鐵槍、長牙槍)、拳套 (鋼爪、破冰爪)、筆 (鐵筆、逝水筆)、暗器 (飛蝗石、袖裡箭)。
  - **防具類**: 男性頭盔 (牛皮帽、勇士巾)、女性頭飾 (五彩巾、彩霞冠)、男性鎧甲 (粗布衣、青銅鎧)、女性衣衫 (絲織衣、流雲衫)、腰帶 (麻線腰帶、精鐵腰帶)、鞋履 (布履、青木屐)、護腕 (鐵護腕、青玉護腕)。
  - **飾品類**: 戒指 (粗銅戒、白玉戒)、香囊 (香囊、彩繡香囊)。
- **核心屬性公式結構**:
  - 每件裝備明確規範有耐久度上限（如標準耐久 `140/140`）、裝備需求等級（0級入門、20級進階等）、製造者（系統/玩家打造），以及專屬屬性加成（`基礎屬性$攻擊 +108`、`基礎屬性$防禦 +25`、`基礎屬性$氣血 +80`、`基礎屬性$速度 +12`）。

### 3.2 世界地圖與場景劃分 (`script\data\sceneid2name.py`)
- **歸檔位置**: Entry 400
- **數據特徵**: 建立了伺服器 Scene ID 與客戶端場景名稱、坐標尺寸、場景用途的映射。
- **代表性場景分類**:
  - **各大主城**: 永澤城 (ID 1001)、天蒼城 (ID 1013)、香葉城 (ID 1007)。
  - **野外修煉區域**: 清溪平原 (ID 1004)、天水平原 (ID 1005)、螢火森林 (ID 1012)、太息林地 (ID 1018)、落雪冰原 (ID 1035)。
  - **特色迷宮/副本**: 海底神殿 (ID 1019)、珊瑚迷宮 (ID 1036)、靈石塔 (1~3層, ID 1039~1041)、古木祭壇 (1~3層, ID 1043~1045)、兔坦卡門陵墓 (ID 1078)。
  - **三大職業師道殿**: 包含南遙、天寧、清嵐三國各自的戰士、法師、術士師道殿。

### 3.3 NPC 隨機對話與背景世界觀 (`script\data\npcrandomchatdata.py`)

- **內容展現**: 完整刻畫了黎明鎮與夜幕鎮之間，兔族（風舞一族、赤瞳族）與狼族（星月一族）在面對魔族入侵時的複雜恩怨情仇與民生百態。

- **涵蓋流派**: 佛家、儒家、道家、巫師、陰陽，以及劍法、刀法、槍法、拳法、筆法、暗器共 11 大門派流派體系。

## 4. 數據導出格式說明 (`tools/data-export/`)

導出的數據集覆蓋主流開發與分析標準：
1. **JSON (`*.json`)**: UTF-8 編碼，保留完整物件巢狀結構，便於前端與 Web API 直接集成。
2. **CSV (`*.csv`)**: 帶有 UTF-8 BOM，相容 Excel、Pandas 與 R 分析工具。
3. **SQLite (`game_data.sqlite`)**: 標準關聯數據庫，建有 `equipment`, `scenes`, `npc_dialogs`, `reward_gifts`, `skills` 五張主表，支援快速索引與複合查詢。

## 5. 數據瀏覽器工具說明 (`tools/data_browser/`)

為了讓開發團隊直觀查閱與檢索數據，本任務構建了雙模遊戲數據瀏覽器：

### 5.1 Web 即時儀表板模式
- **啟動方式**:
  ```bash
  python3 tools/data_browser/app.py
  ```
- **服務監聽**: `http://0.0.0.0:8080`
- **主要特性**:
  - 全響應式深色模式界面（Dark Mode UI）。

## 7. 數據逆向重打包與熱補丁支援 (`tools/data-parser/repack_fls.py`)

為了支援遊戲數據修改（MOD、數值平衡調試、自定義私服數據測試），開發了雙向逆向重打包引擎：

### 7.1 逆向代數編碼公式
對於已修改的遊戲數據，需將其重壓縮並寫入歸檔，同時計算對應的 4-DWORD 索引表項：
$$
\begin{aligned}
r_2 &= ((r_1 \cdot \text{entry\_id} + \text{0x0DF25E}) \oplus \text{compressed\_length}) \pmod{2^{32}} \\
r_3 &= ((r_2 \cdot \text{index} \cdot \text{0x00F718FE} + \text{0x0D59D16C}) \oplus \text{data\_offset}) \pmod{2^{32}}
\end{aligned}
$$
該閉合代數映射確保了**重打包後的二進制歸檔能被原版客戶端引擎無損加載**。

### 7.2 實測驗證
透過 `repack_fls.py --test-patch`，成功修改 Entry 17 武器屬性（短劍基礎攻擊力由 `+108` 修改為 `+999`），並完整重打包為 `tools/data-export/script_modded.fls`。經解碼器校驗，修改後的字串與位元組校驗和完全吻合，驗證了重打包流程的完備性。
